所以这活不是"解除限制"，是"补一条合法的路 + 把来源标清楚"。

### 实现

1. `WorkoutSession.kind?: "planned" | "extra"`（缺省 planned，不破坏老数据）。
2. `POST /api/workouts/preview` 接 `kind:"extra"`；**响应体和落库都要标**——这里踩了个坑（见下）。
3. 加练不挂 `program`：`programStatus` 只认 `completions`，所以 6/12 不会被加练顶掉。
4. 练完照常 `finalize()` → `training_records`/`experiment_records`，与计划内同等对待（它确实是真实训练）。
5. 结算页新增「还想再练一会儿」：提示"单独记一场、不影响今天的计划完成度、不顶替课程进度"，预填 20 分钟 + 上次环境/器械，进训练条件面板；提交时带 `kind:"extra"`。
6. 记录列表显示「· 加练」。

### 坑

1. **`input` 是用户那句话，不是请求体**：preview 里 `const { input, userId, ... } = await body(req)`——`input` 是字符串。我写成 `input.kind === "extra"` 取了半天永远 undefined。正确做法是把 `kind` 也解构出来。这个错我连续犯了两轮（第一次改完看着"没生效"，又去查进程时间，白折腾）。
2. **响应和持久化是两个对象**：`prepareWorkout(result.workout!)` 之后给 `workout` 打标，只影响入库；接口返回的是 `result`。两处都得标。
3. **改文件把相邻行删掉了**：PUT 一个区间时把 `workout.suggestedExercises` 和 `const assignedMode` 两条一起覆盖掉，`configureExperience` 立刻引用未定义变量。还是那句：**改之前 Read，改之后跑一次**。
4. **测试自己留了脏数据**：验证"练完能不能再生成"时用 `demo-investor` 直接调了 preview，结果演示用户多出一场未完成会话（6→7）。后来用 seed 重造复原。教训：**验证也要用临时用户**，这条之前写进过 journal，这次又犯了。

### 验证

- 接口：`kind:"extra"` → `workout.kind='extra'`、`program` 为空、落库带标记
- 完整闭环（脚本实跑）：加练场次练到 completed → `/api/history` 里 `kind=extra` → `training_record` 自动生成
