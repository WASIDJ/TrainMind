# 社区第一批实现 · 2026-11-10

状态：已完成可操作的本地试用版本；完整社区方案仍按后续阶段推进。
设计来源：[社区 PRD](COMMUNITY-PRD.md)、[同路人与关注](COMMUNITY-PATHMATES-AND-CREATORS.md)。

## 入口与页面

主导航变为 **首页 / 课程 / 社区 / 记录 / 我的**。社区有独立 `/community` 地址；内部为 **关注 / 同路人 / 发现**。返回首页时地址恢复 `/`，刷新社区可回到社区。

沿用深紫背景与荧光黄视觉。内容以照片、生活与运动经历为主，不要求附教学或训练证明；空社区展示真实空状态，不自动造用户、计数和附近练友。

## 已实现的范围

| 能力 | 实际行为 |
|---|---|
| 社区账号 | 独立注册/登录/退出，昵称和密码；服务端 scrypt 盐化密码，随机会话凭据仅存哈希，HttpOnly/SameSite Cookie |
| 图文发布 | 公开文字与照片，生活照片/训练经历/恢复日记/找同路人话题，发布额度、幂等重试、删除自己的内容 |
| 照片 | 浏览器缩放、转 JPEG 后上传；每张不超过 600KB；SQLite 保存字节，未发布照片仅本人可读，公开照片随内容权限校验 |
| 关注 | 第一日可关注/取消关注；关注流按发布时间展示已关注者内容，不自动获得私信权限 |
| 点赞与评论 | 点赞/取消幂等、评论、删除自己的评论，正文按文本转义；一次返回最近 100 条可见评论 |
| 个人主页 | 公开昵称、介绍、活动方向、等级、粉丝与关注数、公开分享；“我的社区”提供资料、屏蔽管理与退出 |
| 同路人 | 主动选择方向/阶段/环境/频率/时长；可主动导入当前本机计划的动作 ID 摘要；同时启用匹配的账号才参与推荐 |
| 推荐说明 | 区分“主动选择的标签”和“主动分享的动作结构”；输出可解释共同点，不展示精确相似度或身体相同结论 |
| 恢复记录与等级 | 每上海自然日最多记一次恢复日，累计 0/3/7/14/30/90/180/365 日等级及发布/图片额度；恢复不是训练完成 |
| 屏蔽与反馈 | 双向隐藏内容/照片/推荐并取消关注；举报先为反馈者隐藏内容，处理记录存库 |
| 运营处理 | 本地工具读反馈、隐藏内容、暂停账号并撤销会话，记录处理原因与时间 |
| 数据权利 | 导出本人社区资料、照片、发布、评论、关注、喜欢、打卡与本人反馈；密码确认后删除社区账号和关联数据 |

照片上限：L0 每条 1 张，其余已实现档位每条最多 3 张。视频、长视频权益尚未实现，界面不提供假入口。文字最多 2000 字符，评论最多 1000 字符。发布后删除不返还当日额度。

## 账号、训练与计划的边界

旧的本机训练者 ID 可被切换，不能用它来证明多人社区的身份。因此社区账号没有自动认领、公开或升级旧训练记录，也不会依据客户端传入的 authorId/userId 代他人发帖。社区相关写入均以服务端会话中的账号为准。

主动分享计划的按钮由用户确认提取本机已有计划。服务端只接受目录中存在的动作 ID，计算模式摘要，保存为 `user_shared`。不读取他人训练表，不存重量、次数、伤病、限制原因或原始教练对话。它是用户主动分享的推荐信息，不是已验证的身体或运动证据。

当前尚无安全绑定旧训练账号的迁移流程，因此社区的等级只接了恢复日记录，未自动接入训练完成日；界面明确说明。训练者 ID 与社区登录不会互相冒充或改写训练状态。

## 同路推荐基线

采用透明的初始规则：活动方向、主动目标、已知阶段、环境、频率、时长以及动作模式集合的归一化重合。未知字段不当共同点；双方主动启用匹配，且至少有两个可说明的共同点才进入候选；屏蔽、暂停和已反馈的账号排除。

动作模式至少有两个共同模式时，可给出“主动分享的计划动作结构接近”。没有摘要时按明确选择的方向降级。权重与时长差距仅为实现基线，尚未以关系效果校准；相同默认模板仍可能使区分度不足，不因此输出“高度同路/身体相同”的保证。此版本未使用病史或体重匹配，也没有假装理解未支持运动的完整计划。

## 试用范围与尚未实现

本批面向现有本地应用试用，沿用回环 Host、跨站来源和移动口令防护。没有部署到公开互联网。账号恢复/找回、真实多设备注册体系、自动审核与申诉后台仍需后续完善；不能把本地试用当作已具备对外运营条件。

完整方案中的固定小圈、双向练友与私信、火花、共同周计划、附近约练、位置匹配、商品/优惠券及核销、创作者认证与活动角色，**本批均未开放**。目前普通创作者已能通过发布和被关注积累内容关系。

后续优先：训练账号绑定与有效运动日 → 固定圈/共同目标与真实重复关系 → 双向交流及治理 → 约练与履约 → 合作权益。新增对外能力时分别验收，不把当前不存在的服务放进假按钮。

## 文件与运行

- 服务端：`src/community.ts`；主服务 `src/server.ts` 只接入迁移、路由及静态资源。
- 前端：`public/community.js`、`public/community.css`；`public/index.html` 加导航和独立地址。
- 测试：`test/community.test.ts`，8 项覆盖身份、越权、图片归属、幂等、屏蔽、分页、推荐、删除与重开存储。
- 处理工具：`tools/community-moderate.ts`。

正式本地服务仍按项目约定用 `./start-7b3.sh` 启动。浏览器进入 `/community` 或点击底部“社区”。正式库只做新增社区表迁移，不自动加入示例账号或内容。

操作工具（默认只读）：

```bash
node tools/community-moderate.ts reports
node tools/community-moderate.ts hide-post <内容ID> '处理原因'
node tools/community-moderate.ts suspend-account <账号ID> '处理原因'
```

指定临时库可设置 `TRAINMIND_DB`。处理工具需要由有数据库访问权的本机操作人员执行，没有公开管理路由。暂停账号会撤销其会话，内容与照片均不再公开。
