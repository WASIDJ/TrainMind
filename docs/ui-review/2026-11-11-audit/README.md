# 界面实测审查（2026-11-11）

用无头 Chrome + CDP 在**真实服务**（`./start-7b3.sh`，登录态演示账号 `demo-investor`，另有全新空账号）逐屏截图，390×844 与 320×568 两种视口。不是看设计稿，是看用户打开后真正看到的东西。

## 一、结论先说

后端能力很扎实，但**界面层离"能拿去见客户"还差一截**，问题集中在三类：

1. **图片与文字对不上**——训练屏整屏是一张硬拉照片，做的是鸟狗式；计划页三个不同动作共用同一张缩略图。客户第一眼就会觉得"这是个演示壳"。
2. **关键能力没有入口**——日报、数据导出、体图三个接口前端零引用；"排今天的训练/导入计划"要从首页气泡点进一个**没有"我的"导航条**的旧版仪表盘。
3. **版式缺陷**——社区页悬浮按钮压住卡片正文；休息屏标题被卡片压住；内容溢出是 0，但"压住"比"溢出"更难看。

## 二、逐屏实测（390×844）

| 屏 | 结论 | 具体问题 |
|---|---|---|
| 首页（对话式） | **能看，是最好的屏** | 排版、文案、留白都成立。见 `fresh-home.png` / `home-390.png` |
| 课程地图 | 设计感强 | 关卡、路径、周区域都成立；但**课程名是"4 周 想练全身课程"**——把用户原话直接当标题，像内部变量漏到界面上 |
| 记录 | 能用 | **每场都是"1 动作 · 100%"**：种子数据每场只建 1 个动作，真实用户不会这样，客户会看出是假数据 |
| 我的（档案） | 能用 | "完整场次组数"这种标签不通顺；0 数据时整页都是"尚未/还没有"，缺少引导 |
| 社区 | 有设计感 | **"分享此刻"胶囊压住第二张卡片正文**（PROGRESS 里记作"已知遗留"，但这是客户会第一眼看到的） |
| 计划页 | **有明显硬伤** | 3 个不同动作（鸟狗式/髋铰链/另一下肢）**共用同一张戴哑铃硬拉的照片**；教练卡写着"按经验水平的低剂量默认值先做1组校准"——这是内部实现说明，不该给用户看 |
| 组内训练 | **最严重** | 整屏背景是硬拉照片，做的却是"鸟狗式"；图上写着"语音陪练与动作要点"却没有可点区域；主按钮是**"滑动完成这一组"**但没有任何滑动交互提示与进度 |
| 组间休息 | 有硬伤 | **"组间休息"标题被"下一组"卡片压住**（文字被切断）；底部出现"语音播放失败；可以使用备用按钮继续训练"——灰底技术错误直接暴露给用户 |

## 三、新用户首屏（客户第一次打开看到的就是这些）

用全新账号（无任何数据）实测：

- 首页：正常，四个服务气泡都在。
- 课程：空状态合理（"还没有课程 / 先选器械，再选周期"）。
- 记录：**8 个肌群 × 两行"还没有记录"，占满两屏**；「查看最近训练」「查看训练进度」两个按钮在 0 数据时**仍然可点**。
- 我的：整页 0 与"尚未形成偏好"，没有下一步动作。

## 四、功能可达性（这决定能不能"完整"宣发）

| 能力 | 后端 | 界面入口 | 判定 |
|---|---|---|---|
| 对话首页 / 语音陪练 | ✅ | ✅ | 完整 |
| 课程 + 打卡 + 关卡地图 | ✅ | ✅ | 完整 |
| 记录 / 进度 / 肌群状态 | ✅ | ✅ | 完整 |
| 社区（发布/关注/评论/推荐） | ✅ | ✅ | 完整 |
| 导入别人的计划 | ✅ | ⚠️ 只在首页气泡 → 旧仪表盘 → 训练条件面板里 | **路径 3 跳，等于找不到** |
| 每日日报 | ✅ `/api/report/daily` | ❌ 零引用 | **用户看不到** |
| 数据导出 / 删除 | ✅ `/api/export` | ❌ 零引用（只有社区数据能导） | **"数据资产归用户"这句话没有落地** |
| 人体示意图 | ✅ `/api/body-map.svg` | ❌ 零引用 | 看不到 |
| 模型设置 | ✅ | ⚠️ 仅当模型未配置时报错页里出现 | 配好之后**再也进不去**改配置 |

**注意**：首页点「安排今天的训练」会调用 `intentHome()`，那是 **D33 之前的旧仪表盘**——它有自己的 `#navigate` 顶栏，没有底部导航，进去后回不到「我的」。这是 D33 改造留下的断层。

## 五、美观性判断（直说）

- **设计语言是成立的**：深色 + 荧光黄 + 大字号，社区页和课程地图能站住。
- **但"照片仓库"拖垮了整体观感**：总共只有 6 张教练图（`lin-cover/squat/hinge/pushup` 等），被当作(1)教练头像 (2)首页主视觉 (3)计划缩略图 (4)训练全屏背景 (5)休息背景 (6)结算背景同时复用。**图片与动作无关**时，越大的图越露怯。
- **字体层级偏单一**：大量元素都是粗体大标题（"训练记录/我的训练档案/按你的节奏练"），缺少中间层，扫读时抓不到重点。
- **技术文案外泄**："按经验水平的低剂量默认值先做1组校准""语音播放失败；可以使用备用按钮继续训练""完整场次组数"——这些话是给开发看的。

## 六、建议的优先级（面向"尽快完整 + 能宣发"）

**第一优先：看起来像真产品（1-2 天）**

1. **动作图与说明解耦**：没有对应动作照片时，训练/计划屏**不要**铺教练照当背景，改用纯色渐变 + 大号动作名 + 动作要点（现有 `instructions` 已有数据）。只在 RepDB 有素材的动作上显示动作图。
2. 修三处版式压盖：社区"分享此刻"、休息屏标题、计划页教练卡文案（改成人话）。
3. 记录页每场"1 动作"：重造演示种子，让演示场次是 4-6 个动作的真实结构。

**第二优先：能力可达（1-2 天）**

4. 给日报 / 导出 / 体图加真实入口（我的页一组"我的数据"）。
5. 首页「安排今天的训练」改走对话内多轮，或把旧仪表盘补上底部导航。
6. 导入别人计划：升级为首页一级服务气泡。

**第三优先：新用户首屏（半天）**

7. 记录页 0 数据时隐藏肌群列表、两个按钮置灰并给引导。
