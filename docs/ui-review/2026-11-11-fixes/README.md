# 界面修复第一批（2026-11-11）

针对 [界面实测审查](../2026-11-11-audit/README.md) 里"看起来像演示壳"的问题，按"先修能一眼看出来的、再修口径"的顺序改完第一批。全部在真实服务上用无头 Chrome 复核（390×844），`npm test` 两次 **376/375/1/0**。

## 改了什么

| 问题 | 改法 | 效果 |
|---|---|---|
| 训练屏整屏是**硬拉照片**，做的却是鸟狗式/提踵；计划页 3 个不同动作共用一张缩略图 | `visualImage()` 改成"只在图与动作真的对得上时才出图"：RepDB 有静帧用静帧，自研动作只有名字能对上（深蹲/硬拉/俯卧撑）才用教练照，其余返回 `null` | 不再用无关照片冒充动作图 |
| 无图时屏中间一片黑 | 新增 `visual-text-first` 版式：标题 → 目标数字 → 本组处方 → **动作要点** → 教练 → 底部操作，全部竖排流式（原来全是 absolute，图一撤就散成悬空碎片） | 见 `cue-training-390.png` |
| 动作要点藏在折叠面板里，屏中间反而空着 | 把前 3 条要点搬到明面上（`mountCues`），折叠面板保留 | 训练时抬头就能看到"这一组注意什么" |
| 计划页教练卡写着"按经验水平的**低剂量默认值先做1组校准**" | 新增 `planLead()`，翻成"今天从X、Y 开始，每个动作先用一组找合适的强度" | 内部实现说明不再外泄 |
| 组内屏底部"**语音播放失败；可以使用备用按钮继续训练**" | 改成"这次没读出声音，按屏幕上的提示继续就行"，技术细节只进 `voiceLog` | 不再像产品坏了 |
| "滑动完成这一组"没有任何可拖动暗示 | 加"→ 拖动"提示 + 轨道渐变 + 把手阴影 | 用户知道能拖 |
| 记录页每场都是"**1 动作 · 100%**" | 种子脚本改成每场保留 4 个动作、按真实状态机走完整场（原来写死"只留第一个动作、3 组"） | 变成"3 动作"，结构可信 |
| 社区"分享此刻"胶囊压住帖子正文 | 从 `position:fixed` 移出，放到页头下方的常驻一行 | 不再遮挡任何内容 |
| 课程名"4 周 **想练全身**课程"（用户原话当标题） | 未改（需要产品定标题口径，见下） | 仍是待办 |

## 试错记录（写下来免得别人重踩）

社区那个按钮我改了两次才对：

1. 先给列表加 `padding-bottom:78px` —— **没用**。按钮是 `fixed`，任何滚到它下面的内容都会被盖住，留白只是让最后一张卡片能被滚出来。
2. 改成右下角圆形 FAB —— **更糟**，压住了帖子右上角的"+ 关注"。
3. 最后认清"悬浮在内容上"这个前提本身不成立（卡片几乎占满整宽），改成放在页头下方常驻一行。

同理，训练屏我先试了"内容竖直居中"，结果是上下都空、像没做完；真正的问题是底部操作托盘是 `absolute` 不参与 flex，最后改成固定顶距 + 底部安全区。

## 第二批：把"数据资产"接到界面上

后端早就有 `/api/report/daily`、`/api/export`、`/api/body-map.svg`，但前端**零引用**——"数据资产归用户"这句话没有落地。这一批把入口放到「我的 → 我的数据」：

| 入口 | 行为 |
|---|---|
| 今天的日报 | 生成并落盘 Markdown，同时在弹层里**渲染成可读排版**（标题/列表/表格/体图），不是甩一段 `#` 和 `**` 给用户 |
| 导出全部数据 | 直接下载 JSON 到你本机，并告诉你导出了多少场/多少组 |
| 看肌群体图 | 弹层里显示 8 个部位的上色示意图 + 颜色含义 |

顺手修了两处"内部值外泄"：

- 日报里 `goal` 是枚举（`general_fitness`），原来会原样拼进正文，现在翻成"全身力量"。
- 体图的 `![今天练了哪]` 会让这段 alt 文字在图下再出现一次，已去掉（SVG 自带说明）。

截图：`data-bodymap.png`、`data-report-2.png`（日报滚到表格处）。

## 第三批：动作素材换成 free-exercise-db

owner 要求换掉 RepDB。核对了许可与实际覆盖：

| | RepDB 免费档 | **free-exercise-db** |
|---|---|---|
| 许可 | Term 3 **禁止再分发**（只能每个开发者自己拉） | **Unlicense / public domain**：可商用、可修改、可再分发、无需署名 |
| 覆盖 | 80/102，但我们最常用的 5 个自研动作**全都没有** | 873/876 有真实照片，映射到我们 18 个动作 |
| 形态 | 512px 静帧 | 850×567 横图，每动作起始/结束两帧 |

落地：

- `tools/fetch-freedb-media.ts`：按映射表下载两帧，校验 JPEG magic（远程 404 页也会回 200 文本），
  同时生成 `knowledge/freedb-map.json` 供前端读取。
- 映射**只收动作形态真的对得上的**：鸟狗式、原地快走、站姿活动度、靠墙俯卧撑、跪姿绳索下拉
  在数据集里没有可信对应，明确不映射——宁可没有图，也不贴错图。
- 素材**入库**（2.2MB / 38 文件），与 RepDB 正好相反；`.gitignore` 里写清了原因。
- 训练屏原来是"铺满全屏背景"，横图这么做会裁切留黑边。改成**动作参考卡**：
  起始/结束两帧并排 + 说明，文字版式照旧。

截图：`cue-training-390.png`（徒手髋铰链：两帧照片 + 要点 + 剂量依据）。

## 第五批：对话输入条重做 + 手机预览页 Safe Area

用户截图指出首页底部输入框"很丑"。拆开看确实是三个互不相干的东西挤在一行：
44px 紫色方块「与教练说话」（字号 11px）+ 9px 灰色提示「文字 / 语音，都可以」
+ 44px 荧光黄方块（22px 的 ↑）。三种高度、三种视觉重量，像拼出来的。

改法：
- 单行输入条：`textarea` 自动增高 + 麦克风**图标**键 + 圆形发送键，同一 36px 基线。
- 发送键只在有内容时点亮（`.ready`），空态是安静的灰。原来常亮的荧光黄
  让输入框成为整屏最响的元素，而它其实是最不该抢注意力的。
- 去掉「文字 / 语音，都可以」——图标本身已经说明了，留着是解释图标在说什么。
- 底部 `TrainMind · 你的 AI 训练伙伴` 从 9px 降到 8.5px 且更暗，退回页脚。

**连带修掉两个 bug**（都是这次改 DOM 暴露的）：
1. `public/index.html:397` 原来用 `document.querySelector('#coach-form button')` 取提交键。
   语音键移到前面后它选中的变成了语音键，把麦克风图标覆盖成 `↑`。
   改成按 `#home-chat-send` 取，忙碌态用 `.busy` 类 + 转圈，不再改写图标内容。
2. `voiceUI()` 原先对 `#mic` 直接写 `textContent`（图标会被冲掉）。改成切
   `.listening` 类 + 更新 `aria-label`/`title`，图标由 `data-keep-icon="1"` 保护。

手机预览页 `public/phone-preview.html`：`.screen` 原来只留了顶部 44px 状态栏，
底部没留 Safe Area，Home 条压住 App 底部导航的图标行。改成 `padding:44px 0 14px`
+ `box-sizing:border-box`。

截图：`composer-empty.png`（空态）、`composer-typed.png`（有内容，发送键点亮）、
