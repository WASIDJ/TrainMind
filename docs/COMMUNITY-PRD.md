# TrainMind 社区产品方案：用坚持认识练友

版本：v0.1 产品讨论稿  
日期：2026-11-10  
状态：方向已由用户提出；本文补充的等级、额度、交易规则和上线指标均为建议值，尚未实现。  
关联：[课程与训练现状](PROGRESS.md)、[界面规范](UI-SPEC.md)、[产品决策 D32](../../TrainMind-智能性重设计提案.md)

## 1. 产品主张与本轮共识

**让持续健身的人凭坚持形成社区身份，获得更多表达机会、认识同路人的机会，以及实际消费优惠。**

用户的核心判断是：健身有社交属性，健身的人更容易玩到一起。社区不只用于晒成绩，也应该能让人找到一起练的朋友，形成稳定的小圈子。

用户明确提出的方向：

- 连续打卡天数是显眼的社区标识，不同天数对应不同等级。
- 等级越高，可以发布更多内容，购买指定商品或服务有更高优惠。
- 连续打卡两周后，可以解锁“滴滴别人”、约附近的人一起练等能力。
- 权益主要属于社区、身份和消费，不是训练指导质量的分层。

本方案保留上述方向，并补足四件事：怎样把休息日算进坚持；怎样让刚加入的人也能参与；怎样让打招呼转成双方愿意的约练；怎样避免等级成为刷量和骚扰的工具。

**核心闭环：按节奏训练与恢复 → 积累连续打卡身份 → 分享与互动 → 解锁联系练友 → 一起练 → 继续训练与分享。** 优惠是坚持后的额外回报，不作为这条闭环成立的唯一理由。

### 成立条件与待验证假设

这是一个值得验证的产品方向，尚不能视为已证明能提高留存的机制。

| 假设 | 要观察的行为 | 若不成立怎么办 |
|---|---|---|
| 用户愿意用坚持而非身材建立身份 | 佩戴徽章、查看练友档案、分享训练卡 | 调整展示和内容模板，不直接增加更多等级 |
| 同时间、同场地的人更容易形成关系 | 接受招呼、确认约练、再次约同一个人 | 收缩到具体健身房或小圈子，先解决人群密度 |
| 14 天门槛能增加投入感，又不挡住新用户 | 达标前的社区参与与达标后的首次招呼 | 保持新手内容互动，单独测试门槛，而非一次改所有权益 |
| 折扣能被用户感知且成本可控 | 领券、核销、单次补贴成本 | 收缩商品范围或改固定金额券，不靠虚高原价维持吸引力 |

## 2. 谁会使用、为什么留下

| 人群 | 当前需要 | 社区给予的价值 |
|---|---|---|
| 刚开始健身的人 | 怕不懂、怕融不进去 | 同阶段内容、新手友好标签、低门槛分享，不必先有好身材 |
| 已坚持两周的人 | 想找到能一起练的人 | 解锁打招呼，按场地和空闲时间找练友 |
| 稳定训练的人 | 希望被看见，也愿意输出 | 更大的发布空间、身份装饰、发起小型约练 |
| 偶尔中断又回来的人 | 想继续，不想失去既有关系 | 历史里程碑与已建立联系保留，从今天重新累计 |
| 合作健身房或品牌 | 希望接触持续参与的用户 | 有范围、有成本上限的权益，不靠群发私信获客 |

社区身份表达的是“我在持续参与”，不是专业资质、身体水平、真人安全认证或约练履约保证。

## 3. 连续打卡：连续照顾自己，不要求连续训练

### 3.1 什么算一天

同一账号同一自然日最多贡献 1 个打卡日。一天内练两场、发十条内容、买东西，都不会多算天数。

| 当天行为 | 是否计入连续打卡 | 是否计入训练场次 |
|---|---|---|
| 完成本平台一场有效训练 | 是，自动点亮训练日 | 按原有训练记录口径 |
| 正常休息日主动提交恢复打卡 | 是，点亮恢复日 | 否 |
| 因不适停止训练后主动记录恢复状态 | 是，计恢复日，不要求继续练 | 不把中止训练伪装成完成场次 |
| 只登录、浏览、点赞、发帖、购买 | 否 | 否 |
| 手动填写平台外训练 | 首版可作为自述内容发布，不自动计入升级依据 | 不写入平台完成场次；后续单独设计接入 |
| demo、测试会话、预览、空跑会话 | 否 | 否 |

**有效训练日的首版建议口径**：账号下存在服务端记录的 `completed` 训练，且至少有一条已确认完成的组记录；保留原始来源。它证明平台记录了一次完成操作，不声称验证了真实身体活动。不能仅凭客户端传 `dataOrigin=human` 获得资格；生产环境需由服务端区分普通训练与演示/测试。

恢复打卡只需一次轻交互，例如“今天是恢复日 → 精力：不错 / 一般 / 疲惫 → 记录”。不强制写字、拍照、上传健康信息或做动作。公开卡片只展示“恢复日”，精力等具体状态默认私密。训练日也可以记录恢复，最终仍只算 1 天。

为了避免只靠登录式恢复记录获得陌生人联系权益，**14 天解锁额外要求这段连续周期内至少有 2 个不同日期的有效训练日**。这是建议的最低参与门槛，不是训练处方；不要求用户超过个人计划频率，不用补练换资格。若连续 14 天全部是恢复打卡，仍展示 14 天坚持身份，页面提示联系资格尚未满足，不抹掉恢复投入。

### 3.2 身份卡怎么展示

建议名称：**坚持天数**。页面同时说明“训练与恢复都算，登录不算”。

示例：

> 林澄 · 同行者  
> 连续坚持 18 天 · 本周期训练 6 天 / 恢复 12 天  
> 最长连续 32 天 · 晚间力量训练 · 希望找固定练友

公开默认只展示昵称、等级、连续天数与用户主动选择的兴趣标签；训练/恢复构成在本人视图显示，公开需另行开启。头像可以不用真人照片，不要求公开身材、体重或运动能力。

- `currentStreakDays`：当前连续天数，今天尚未打卡时保留截至昨天的天数并提示“今天待打卡”。
- `longestStreakDays`：历史最长连续天数，明确标成“最长”，不冒充当前连续。
- `earnedLevel`：达到过的最高等级，正常中断后保留。
- `contactUnlocked`：曾达到连续 14 天并满足该周期 2 个有效训练日的里程碑资格，正常中断后保留。
- `accountStanding`：账号当前是否正常、受限或封禁，独立于等级；高等级同样受限制。

连续周期只有在整天都没有有效打卡、该日结束后才中断。当天还没打卡不能立刻显示“断签”。当天已有恢复记录，后续完成训练时只更新当天类别和训练计数，不增加天数。

### 3.3 中断、回归、补录与时间边界

- 正常漏一天：当前连续重新开始，历史最长、已获得等级、联系里程碑、已有朋友保留。不给付费补签或清空等级惩罚。来源记录被撤销、确认作弊或用户要求连同成就删除时，可以重算并撤回不再成立的资格，记录原因并提供申诉，不能把规则更正混成普通断签降级。
- 没有打卡时不公开“缺席名单”，提醒默认只在应用内，可关闭；不把好友变成监督者。
- 本人查看日历可区分训练日、恢复日、未记录日；公开不展示精确每日出勤轨迹。
- 首版不允许用户自由补签以升级。平台故障造成的缺失，由服务端事件与处理记录修复，不能随意购买天数。
- 社区试点按 `Asia/Shanghai` 的自然日计算，服务端统一判定，客户端改时间无效。跨午夜训练按完成日归属；离线事件首版需在联网确认后计入，不让客户端时间自行决定升级。
- **与现状的关系**：既有训练统计 D23 按服务器本地时区。社区首版明确固定业务时区，部署在上海时区时两者一致；以后若支持跨时区，需要先统一边界规则，不静默修改历史训练归属。
- 注册前的历史记录不追溯补齐恢复日。账号绑定后的既有真实训练只能在来源可追溯时迁移，不能从缺失日期推算连续天数。
- 删除训练原始数据时，同时说明是否保留不含细节的社区成就凭据：用户可选择保留成就或一并删除；一并删除则重算相关等级资格，已核销订单保留必要交易状态，不能因删数据重复领券。具体保留期限在实际发布前单独制定。

## 4. 等级和权益：每一档都有能感知的变化

以下为**建议配置**，目的是讨论权益梯度，所有额度均由服务端控制并可版本化调整，不代表已上线承诺。

| 等级 | 达成条件 | 动态发布上限 / 日 | 表达能力 | 向陌生人“滴滴” / 日 | 约练能力 | 指定合作商品目标优惠* |
|---|---|---:|---|---:|---|---|
| L0 初来 | 加入社区 | 1 条 | 文字、1 图、训练卡 | 0 | 浏览活动、收藏 | 公开活动价 |
| L1 起步 | 曾连续坚持 7 天 | 2 条 | 每条最多 3 图、7 天徽章 | 0 | 浏览和关注活动 | 9.8 折 |
| L2 同行 | 曾连续坚持 14 天 | 3 条 | 每条最多 9 图、30 秒视频 | 3 | 满足联系资格后可申请/发起 2–4 人约练，同时最多 1 场 | 9.7 折 |
| L3 稳定 | 曾连续坚持 30 天 | 5 条 | 60 秒视频、系列记录 | 5 | 同时最多 2 场，可创建最多 20 人练友圈 | 9.5 折 |
| L4 深耕 | 曾连续坚持 60 天 | 8 条 | 图文合集、身份装饰 | 8 | 同时最多 3 场，小圈子协作管理 | 9.3 折 |
| L5 长跑 | 曾连续坚持 100 天 | 10 条 | 3 分钟视频、里程碑主页 | 10 | 同时最多 3 场，申请社区共创与合作活动名额 | 9 折 |

\* 优惠为针对参与活动的指定商品的讨论目标，非全站保证；需商家签约、成本核算和规则上线后才对外展示。没有合作货盘时显示“权益筹备中”，不做可领取假券。

补充规则：

1. 等级只取历史最长连续天数；L2 以上的陌生人联系与用户约练，还须满足独立的联系里程碑、账号验证、成年与正常账号状态。14 天纯恢复用户可获得 L2 表达权益，联系入口清楚说明差额条件。
2. 天数不能付费购买。消费、充值、订阅不会绕过 14 天门槛，也不能提高陌生人接收方的权限。
3. 基础浏览、点赞、收藏、合理评论从第一天开放；新用户能被看见，不必熬到第 14 天才参与社区。评论使用统一反刷限制，不刻意限制到无法交流。
4. 配额是最大值，不是每天任务。不在用户界面制造“今天还差几条没发”的压力。
5. 自己保存的私密训练记录不受发帖额度限制。训练结束只生成私密卡片，用户选择后才发布。
6. 发帖额度按成功提交计数；删除或审核退回不返还当天额度，平台技术失败不扣额度；同一内容重试保持幂等。界面在发布前说明剩余额度。
7. 已建立的双向关系正常聊天不消耗“滴滴”额度；仍有统一反刷规则。任何级别都不能无上限触达陌生人。
8. 共创、圈主或活动组织角色另外审核，不由等级自动授予专业背书、免审核或运营权限。

## 5. 社区内容：先让人认识彼此，再扩展形式

### 5.1 首版内容类型

| 类型 | 用户要表达什么 | 产品提供什么 |
|---|---|---|
| 训练打卡 | 今天练了、练后感觉如何 | 可编辑卡片：坚持天数、课程阶段、自选感受；次数来源严格沿用原记录 |
| 恢复日记 | 今天不练，也在照顾自己 | 简短恢复卡，不公开具体健康状态 |
| 成长记录 | 一段时间以来的变化 | 周/月里程碑、自选照片，发布前预览与隐私确认 |
| 找练友 | 我什么时候、在哪里附近、想练什么 | 结构化约练卡，避免只发“有没有人” |
| 经验与问题 | 新手困惑、器械体验、练后分享 | 话题标签；个人经验与平台指导分开展示 |

发布图片或视频是独立的主动上传：不得把现有本地影像留档自动上传社区。本人相册中出现他人时提供裁剪/遮挡入口和发布提醒。

### 5.2 信息流与圈子

首版推荐页签：“关注 / 同路人 / 同城”。附近约练从同城进入；“同路人”按用户主动选择的训练阶段、项目和空闲时段组织。

- 排序先看内容相关性、时效、重复度和内容质量，等级只是身份，不自动垄断曝光。
- 明确给新用户与小体量创作者探索位置，避免高等级用户靠额度淹没信息流。
- 首版不设身材榜、训练量榜或发帖数量榜。可以提供“本周第一次来”“坚持两周”等共同话题。
- 关注不等于允许私信。评论区不提供绕过屏蔽的 @、回复或联系方式轰炸。
- 练友圈按场地/时间/项目建立，如“周二周四晚·徐汇力量训练”；首版普通圈不承接付费教学和推销。

## 6. “滴滴”：一次有上下文的邀请

### 6.1 资格与双方选择

“滴滴”是一个可接受、可忽略的招呼请求，不是直接推送进私人聊天。

发送条件：联系里程碑已获得；账号通过实际账号验证；首版声明成年；账号状态正常；额度充足；双方未拉黑。接收条件：对方已获得联系资格，并主动开启“接收练友招呼”。公开资料和附近发现是另外两个独立开关，默认均不因升级自动开启。

默认接收上限为每天 10 个新请求，可调低或关闭。达到上限时暂停新投递；不向发送者透露对方是否拒绝、何时在线或收到多少请求。

### 6.2 发送流程

1. 在动态、同路人或附近页看到对方的公开档案。
2. 点“滴滴”，先看到共同点，例如“都选了晚间训练 · 都在同一个片区”。
3. 选择招呼意图：“想找固定练友 / 想一起练这一次 / 想交流器械”，可补充最多 80 字。
4. 未建立关系前不发送图片、链接、电话或外部账号；不支持批量复制发送。
5. 确认发送并扣除 1 次额度。显示“已发出，等对方愿意回应”，不显示已读。
6. 对方收到请求卡，可接受、忽略、拒绝、拉黑或举报，不接受也不必解释。
7. 接受后建立双向练友关系，开启文字聊天与约练卡；图片等能力按后续版本开放。

### 6.3 请求与关系状态

`未发送 → 待回应 → 已接受 / 已拒绝 / 已过期 / 已撤回`；关系另有 `正常 / 已解除 / 已屏蔽` 状态。

- 请求 7 天未回应自动过期；同一对账号只允许一个待回应请求，未回应不允许追加消息。
- 拒绝或过期后 30 天内不能再次向同一人发起；撤回同样不返还额度、不绕过冷却。
- 同时待回应请求最多 10 个，即使每日额度更高也受总量约束。
- 不暴露拒绝原因或精确拒绝时间，发送方统一看到“当前无法继续联系”。
- 拉黑立即阻断请求、聊天、推荐、约练申请和通过同一活动绕行接触；已有活动提供退出与运营处理入口。
- 解除关系后不能继续发消息，也不能通过取消关注重新触发新请求。
- 新升级、异常批量行为或申诉期间可降低陌生触达额度，规则不能因等级高而豁免。

### 6.4 熟人路径

新用户可以通过双方主动交换的邀请码/二维码添加已认识的人，双方确认后联系，无需等 14 天。邀请码不出现在附近页，不允许批量搜索手机号或通讯录。该路径只服务已认识的人，不能成为陌生发现绕过门槛的入口。

## 7. 附近约练：匹配能一起练的人

### 7.1 附近发现

对方开启附近可见，才有机会出现在附近页。用户可以选大致片区，无需始终开启定位；拒绝定位仍能使用内容与同城手动筛选。

候选排序优先考虑：同场地或同片区、时间窗口重合、训练项目、是否接受新手，再考虑距离档位。不能仅按颜值、性别或消费能力排序。

公开卡片示例：

> 小舟 · 同行者 · 连续坚持 16 天  
> 徐汇片区 · 工作日 19:00–21:00 · 力量训练  
> 接受新手 / 倾向小团体 / 想找长期练友

不展示精确坐标、实时位置、实时在线状态、固定出勤轨迹或“刚刚离开健身房”。距离采用较粗分档（如同片区、邻近片区、同城），首版不提供可反复刷新逼近的米级距离。精确场地是活动信息，不等于某人的当前位置。

### 7.2 发起约练卡

首版支持公共健身房、公园等公开场地的免费 2–4 人约练，不支持私人住址或私下收费教学。

必填字段：标题、日期、开始/结束时间、场地、训练项目、人数、是否接受新手、预计自付场馆费用、加入方式。费用即使为 0 也写清楚；平台首版不代收约练费用。

建议标题：“周四 19:30 · XX 健身房 · 力量训练找 1 位练友”。同场不强制同剂量，每个人沿用自己的训练安排。

### 7.3 完整流程

| 步骤 | 产品行为 |
|---|---|
| 发起 | 校验资格与同时开放活动数，公开活动卡等待申请 |
| 申请 | 申请者同样具备联系资格；附可参加时间与一句说明；每天最多提交 3 次新申请，不与滴滴互相绕额度 |
| 确认 | 发起者接受后占位，数据库原子限制名额；未获同意不建立聊天关系 |
| 联系 | 为已确认成员开放本次活动文字会话；参加活动不自动互加练友，不公开手机号 |
| 变更 | 时间、地点、费用等关键变更需成员重新确认；拒绝变更可退出，不记失约 |
| 见面 | 在约定公共地点集合，用户可将活动卡通过系统分享发给自己的可信联系人，不自动发送 |
| 结束 | 双方可各自确认“见到了 / 没去成 / 对方未到”；默认 48 小时内完成反馈 |
| 再练 | 双方主动选择“愿意再一起练”，可互加练友或发起下一场，不自动生成重复约练 |

同一人同一时段不能确认多场重叠约练；每人最多 3 个待处理申请。活动卡可取消，取消立即通知已确认成员并关闭新申请；未到开始时间的退出不公开羞辱。重复迟到/失约只在有上下文且可申诉时限制新的约练资格。

### 7.4 履约与纠纷

首次评价优先用结构化反馈，避免把约练变成外貌评分。等级不替代履约记录，两者分别展示。单方面“对方没来”的反馈不直接形成公开失约结论；有冲突时标待处理，由运营核查，严重行为可以先暂停新联系再处理。

双方确认见面只能作为“双方反馈一致”的约练记录，不宣称平台已定位验证。不得为了证明赴约强制上传定位、自拍或两个人的合影。

活动结束 7 天后关闭临时会话的新消息；已成为练友者继续在双方聊天里联系。退出社区、拉黑或举报的入口始终可用。保留证据的具体期限需要在上线规则中确定，不无限保留位置与聊天。

## 8. 优惠权益：给坚持一个实际回报

### 8.1 先做哪些权益

优先考虑运动服饰、小器械、合作健身房体验/次卡、公开团体活动。首版优先定额或封顶券，避免一开始建设全品类商城。品牌与场馆用独立的合作身份展示，不能伪装成高等级普通用户。

三类权益可以并行：

- **长期身份权益**：头像框、徽章、里程碑主页，达成后持续保留。
- **月度消费权益**：按已获得等级领取指定优惠，每账号每月 1 张，具体商品与上限明确。
- **限额活动权益**：合作场馆体验或社区活动名额，采用明确报名/抽签规则，不承诺人人有库存。

### 8.2 折扣约束与示例

每个商品必须分别配置适用等级、有效期、库存、最高优惠金额、是否可叠加、承担补贴方、退款处理与最低成交价。同品同条件比较时，高等级应不差于低等级；结算自动选最优可用方案，避免会员价反而更贵。

建议折扣只覆盖参与的 SKU/服务，首版每月补贴预算按用户封顶，例如 20 元。这是测算参数，不是当前可领取权益。

示例：标价 199 元，供货成本 140 元，履约与支付等变动成本合计 15 元。9 折成交 179.10 元，订单贡献为 `179.10 − 140 − 15 = 24.10 元`。若要求最低贡献 20 元、单用户月补贴上限 20 元，本单优惠 19.90 元才在这组假设下成立。若广告、退货或其他实际成本尚未计入，需纳入后重新算，不能把该示例当成实际利润。

**购物不是升级任务**：没有消费也能升到最高等级。下单不会点亮打卡日，消费金额不会增加陌生人接触额度。

### 8.3 券的状态与核销

`可领取 → 已领取 → 已锁定订单 → 已核销 / 已过期 / 已作废`。

同一账号、同一权益周期只能领取一次，重复点击幂等。退款不产生第二份补贴：规则允许时归还原券或原周期领取状态，不能凭退单刷券。若采用商家侧核销，使用短时一次性码及商家确认回执，不使用可无限传播的公共优惠码。

不在社区首版直接上线完整商城。若试点期没有明确的合作商家、售后责任和核销能力，只展示权益说明；实际领券要等真实供给可兑现。

## 9. 核心页面与信息架构

建议主导航调整为 **首页 / 课程 / 社区 / 记录 / 我的**。先做页面原型确认 320px 窄屏下五项入口的触达，再替换正式导航；本次仅文档，不修改现有界面。

| 页面 | 用户最先看到 | 主要动作 |

| 社区首页 | 关注 / 同路人 / 同城；本人坚持身份小卡 | 浏览、互动、发布 |

| 练友档案 | 坚持身份、公开训练标签、愿意怎样一起练 | 关注、滴滴、查看约练 |

### 关键文案示例

- 第 1 天：“今天已经留下一步。先看看和你同阶段的人。”
- 第 7 天：“连续坚持 7 天，起步徽章已点亮。你可以分享更多记录了。”
- 第 14 天且满足联系条件：“两周坚持，解锁练友招呼。遇到合拍的人，可以滴滴一下。”
- 第 14 天但训练日不足：“两周坚持已记下。练友联系还需本周期 2 个训练日；恢复优先，按自己的计划来。”
- 当前中断：“从今天继续。你拿到的徽章和练友都还在。”
- 对方关闭联系：“对方目前不接收招呼，可以先关注公开内容。”

## 10. 一段真实使用旅程

小舟刚开始居家训练，第一天完成一场后分享了一张卡片，在“同路人”看到同阶段的人，也能评论互动。

接下来她按每周三次训练的节奏进行，休息日只记录恢复状态。第 7 天获得起步徽章，可以多发一条，也能领到已有合作商品的对应权益；没有合作供给时不显示假优惠。

第 14 天，她已经有多个有效训练日，解锁练友招呼。她主动开启同城发现，看到同片区、同样偏好晚间力量训练的阿远。她发送“想找固定练友”的招呼，阿远同意后两人才开始聊天。

他们确定周四在公共健身房一起练，各练各的计划。第一次结束后，都愿意再一起练，于是形成稳定联系。

后来小舟出差漏了两天，当前连续天数重新开始，已获得的等级、练友关系和联系资格保留。她不必为了保留关系，在出差期间临时补练。

这条旅程要验证的是“坚持带来身份，身份带来关系，关系帮助人愿意继续来”，不是“为了发消息不得不每天训练”。

## 11. 防刷、内容治理和位置控制

这些能力随发布、陌生人联系和约练一起交付，不能靠高等级天然可信来替代。

| 风险 | 首版处理 |
|---|---|
| 只刷恢复、伪造训练、批量账号 | 14 天联系门槛含 2 个训练日；来源可追溯；账号验证与反刷；异常可人工复核，不声称能验证运动真实性 |
| 高等级群发骚扰 | 双方选择、每日与待回应总量限制、同人冷却、屏蔽举报、处罚优先于等级 |
| 位置被反复探测 | 附近默认关闭，粗片区，不提供可枚举精确距离；不展示固定实时行踪 |
| 新手被排除、身材焦虑 | 第一天开放内容互动；等级不统治推荐；不按体重、颜值或训练量排榜 |
| 内容/照片侵权与广告 | 发布审核、举报、申诉、处理记录；商业合作独立标识；训练影像不自动上传 |
| 私下收费、虚假教练 | 首版约练限定免费同伴活动；等级不是教练认证；商业服务走后续独立流程 |
| 线下骚扰与失约 | 公共场地、小人数、关键变更重确认、活动内屏蔽举报、纠纷处理；不靠免责声明代替运营 |
| 优惠倒卖与反复核销 | 账号绑定、短时一次性码、领取/核销幂等、退款规则与补贴封顶 |

首版陌生联系与线下约练仅面向 18 岁及以上用户，作为试点产品范围。年龄与身份核验方案、内容处理机制、数据使用与商家条款需在对外发布前落实，本文不是法律结论。

用户应能分别控制：档案是否公开、内容可见范围、是否附近可见、是否接收招呼、是否允许被推荐、通知设置。关闭附近后，从发现结果及时移除，并清理缓存；不要求删除整个账号才能退出社交。

没有站内举报、处置和申诉能力时，不开放陌生人联系和约练。运营需有可执行的严重事件响应机制；试点有人值守，避免只是放一个无人处理的按钮。

## 12. 与现有系统的衔接及数据边界

当前项目已有课程、训练完成记录、打卡日历、关系进度、导出/删除与本地影像方向，但没有完整的多人社区系统。

**现有训练者 ID 切换与请求中携带 `userId` 的方式不能直接作为社区账号体系。** 社区发布与读取私人消息必须先建立服务端认证、资源归属校验与账号恢复。请求中的发帖人、收件人权限和等级不能由客户端自报。原有演示入口与真实账号域需隔离。

建议新增的数据概念（用于范围估算，非最终数据库设计）：

| 概念 | 最少需要记录 | 主要约束 |
|---|---|---|
| 社区档案 | 账号、昵称、公开标签、可见性开关、年龄范围状态 | 用户资料与训练原始记录分开 |
| 每日打卡 | 账号、业务日期、训练/恢复类型、来源事件、时区 | 账号+日期唯一，服务端计算 |
| 连续与里程碑 | 当前/最长、等级、联系资格、规则版本 | 可重算，保留授予与撤回原因 |
| 内容与媒体 | 作者、正文、可见范围、来源卡片快照、审核状态 | 私密媒体必须再次确认才能公开 |
| 招呼与练友关系 | 双方、请求状态、冷却、接受时间、屏蔽状态 | 双方关系与发送额度原子校验 |
| 约练 | 发起者、地点范围、时间、名额、申请与成员状态 | 防超员、防重叠、关键变更重确认 |
| 权益与券 | 规则版本、周期、领取、预算、核销、退款状态 | 同周期领取唯一，一次性核销 |
| 治理记录 | 举报、处理状态、限制原因、申诉 | 最小权限访问，不向被举报者泄露举报人 |

所有接口统一按服务端账号授权，私密档案、会话与活动成员必须校验读取权限。媒体直链不可绕过可见性；删除或撤回需连同预览、缓存与索引失效。位置数据不混入普通内容埋点。

训练卡只从现有事实生成：推定次数不变成“实测进步”，恢复打卡不变成课程完成，约练反馈不变成训练完成，社区等级不反向调整训练剂量。用户导出与删除要覆盖新增的公开内容、消息、约练和权益记录，并说明与他人共同内容及交易记录的处理方式。

## 13. 分期上线：先做成一个小范围闭环

### P0：完整的小范围社区试点

选一个城市的少量相邻场馆或一个已有真实用户群，不一次开放全国附近发现。人数与地域密度要足以出现同时间能一起练的人；等待 14 天资格形成，不伪造高等级账号或虚构附近练友。

必须包含：

- 服务端账号认证与账号归属、社区加入和退出。
- 训练/恢复打卡、连续身份、0/7/14/30 天等级；更高档先展示规划，不要求首日全部实现。
- 图文、训练卡、关注/评论、公开档案与私密记录分离。
- 14 天后“滴滴”、双向接受后的文字聊天。
- 片区与时间筛选、免费小型约练、取消与结束反馈。
- 屏蔽、举报、内容处置、申诉与数据删除/导出。
- 权益说明；有真实合作供给才开一类可核销优惠券。

视频、完整商城、大规模群聊、圈子管理和自动匹配可后置。不是先放出陌生人消息，再等有问题后补治理。

### P1：稳定练友和有限合作权益

在首轮确实有人接受招呼、成功约练且愿意再约后，增加固定练友圈、视频与成长合集、60/100 天等级、商家权益与核销对账。把“第二次一起练”作为重点，而不只是增加好友数量。

### P2：扩城市与社区共创

地域密度、治理处理与订单能力都能维持后，再扩城市、组织者角色和品牌活动。订阅或商业合作可以增加商品/内容供给，不出售绕过对方意愿的触达能力。

## 14. 如何判断社区值得继续做

**核心指标：每周形成至少一次双方确认共同训练的练友关系对数，以及其中后续再次约练的比例。** 它仍是用户反馈口径，不当作平台观测到的真实到场。

| 阶段 | 指标与定义 |
|---|---|
| 加入 | 进入社区后主动完成档案/发帖/互动的用户比例，区分只浏览 |
| 坚持 | 第 7/14 天有效打卡到达率，同时分别看训练日和恢复日构成 |
| 联系 | 获得资格 → 发送首次招呼 → 被接受 → 有双向交流，每步分开统计 |
| 约练 | 已确认活动 → 双方确认见面；只统计双方一致反馈，不把单方点击算成功 |
| 关系 | 首次约练后 28 天内，是否再次与同一练友确认共同训练 |
| 训练 | 社区用户是否继续按自己的计划训练；不能用增加额外训练量代替留存 |
| 内容 | 发帖后的有效回应、内容被屏蔽/举报比例、新手获得回应的情况 |
| 商业 | 领券到核销、每人补贴成本、订单贡献、退款和核销异常 |
| 体验保护 | 每千次投递招呼的拉黑/举报、定位投诉、严重事件处理进度、退订情况 |

先用试点首两周建立基线；14 天联系资格形成后再观察至少 4 周的联系与复约，不把首周没有约练判定成失败。用户原本就愿意坚持，不能仅比较高等级与新用户就声称社区带来提升；有样本条件时按加入时间与训练基线分组，或做明确的随机试验。

试点出现严重的账号越权、位置泄露或核销漏洞时暂停受影响能力；一般低转化先看是人数不足、时间不合、邀请不清楚还是门槛影响，不盲目增加骚扰额度。具体商业转化目标在拿到基线和货盘后再定，不编造“必然提升多少”。

## 15. 验收场景：后续开发必须说得清楚

| 场景 | 预期 |
|---|---|
| 连续 14 天，4 天训练、10 天恢复 | 坚持 14 天，获得 L2 与联系资格；仅 4 个训练日，不变成 14 次训练 |
| 连续 14 天全部恢复 | 获得 L2 表达权益；联系资格未满足；不引导补练 |
| 同日多场训练并发多个请求 | 当日只算 1 天，连续值不重复递增 |
| 今天未打卡，但昨天有 | 显示原连续值与“今天待打卡”；明天确认漏一天后才中断 |
| 已获联系资格后漏一天 | 当前连续重新计，等级、联系资格和已有练友保留 |
| 第 14 天但对方没有开启接收 | 无法向其投递；自身等级不能覆盖对方设置 |
| 被拒绝后撤回/重新关注 | 仍受同一对账号冷却约束，不能继续发消息 |
| 高等级账号被限制或被对方拉黑 | 服务端拒绝联系；不能通过评论、活动申请绕过 |
| 两人同时申请最后一个名额 | 至多一人成功确认，无超员 |
| 发起人改地点/费用 | 参与者重新确认，不接受者退出且不记失约 |
| 关闭附近可见与定位权限 | 从发现结果和缓存移除；既有约练按活动范围处理，不继续显示实时位置 |
| 重复点击领券或并发核销 | 只领到一张、只成功核销一次，不超预算 |
| 客户端改 userId、等级、时钟 | 不能冒充发帖、读取别人消息、升级或重复领取 |
| 导出/删除社区数据 | 覆盖新增数据，界面说明成就凭据、共同会话与订单的处理结果 |
| 不选择分享训练影像 | 影像仍保留在原私密范围，不自动上传 |
