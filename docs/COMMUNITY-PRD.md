# TrainMind 社区产品方案：让固定练友成为留下来的理由

版本：v0.3 同路人、关注与运动生活理念补充稿
日期：2026-11-10
状态：产品方向来自用户；公开图文、关注与主动摘要推荐已完成首批本地实现，详见[实施范围](COMMUNITY-IMPLEMENTATION.md)。完整等级、火花、约练及其他实验参数仍属待验证方案。
关联：[现状](PROGRESS.md)、[界面规范](UI-SPEC.md)、[产品决策 D32](../../TrainMind-智能性重设计提案.md)、[竞品研究与证据](COMMUNITY-MECHANISMS-RESEARCH.md)、[同路人与关注设计](COMMUNITY-PATHMATES-AND-CREATORS.md)

> 本版取代 v0.1 的“历史最高连续天数决定等级”和“必须等到第 14 天才开始结识陌生练友”建议。保留按坚持建立身份、等级带来社区与消费权益的方向；将等级、近期运动状态、人与人的火花分开，优先帮助新用户在第一周遇到愿意持续来往的人。

## 1. 社区目标：让运动成为健康、活力与幸福生活的日常

用户本轮明确：社区面向希望通过运动改善生活的不同人群，容纳不同项目、身体条件和恢复需求；关注与创作者是必要组成。运动理念表达健康、生活活力与幸福，不以自律考核定义一个人的价值，也不将“生命强度”误写成训练强度。

两项新增核心价值：**用计划相似发现能互相理解的同路人；用关注关系持续看到认同的创作者与运动生活。** 前者连接正在做相近事情的人，后者容纳项目不同但理念相通的人；再通过固定圈、练友和共同经历沉淀关系。

个性化计划可以有可比较的结构共同点；计划相似不反推身体状况相同。平台可培养和支持值得关注的创作者，但不把粉丝多、等级高等同专业资质或精神引领已被证明。完整定义见[补充设计](COMMUNITY-PATHMATES-AND-CREATORS.md)。

**让用户在这里拥有固定练友、稳定的小圈子、共同训练的安排与回忆，愿意和这些人继续使用 TrainMind。**

这是用户明确提出的战略判断：单独的软件功能容易被替代；当用户在同一个地方持续与做相同事情的朋友来往，对平台的忠诚度可能更高。我们将它作为需要验证的产品假设，而不把“纯软件必然失败”写成已证明的规律。

社区壁垒需要的具体资产：

1. **相互认识的人**：有人知道我在练什么，会回应我。
2. **固定的小圈子**：同阶段、同时间或同场地的一小群人，重复见面。
3. **一起安排的事**：下周的训练时间、共同的小目标、已经约好的活动。
4. **共同经历**：一起坚持过的周数、训练记录、双方愿意保存的合照和里程碑。
5. **可见的身份与认可**：长期投入得到记住，休息与暂时离开不会抹掉一切。

等级、火花、折扣分别支持身份、关系提醒和额外回报。单纯提高签到次数、消息数或打折力度，不能证明关系壁垒已形成。

**核心闭环：开始训练 → 第一周有人回应并重复来往 → 固定练友/小圈子 → 共同安排训练、分享恢复 → 形成共同经历 → 带着关系回来。**

### 本版对 v0.1 的修正

| 原建议的问题 | 修正 |
|---|---|
| 0/7/14/30/60/100 是讨论值，没有解释哪些来自资料、哪些是判断 | 引入竞品事实表，逐个解释首周、月度、季度与年度节点；明确无行业统一最佳天数 |
| 一个人的连续天数同时承担身份、联系门槛与关系维系 | 累计打卡用于等级；个人近期运动状态只显示在练/休整/暂歇；双人火花独立计算 |
| 漏一天影响连续展示，但历史最高保留，又没有说明为什么回来 | 累计身份不清零；火花会降温/熄灭；回来看到熟悉的人、共同安排和历史，而不只有一个数字 |
| 到第 14 天才建立陌生联系，可能拖慢首次关系形成 | 第一天进运营维护的新手小圈；第 7 天建议开放少量陌生招呼；第 14 天扩展约练 |
| 圈子、共同目标被放到后续 | 固定小圈与共同周目标进入首版核心，完整商城和长视频后置 |

## 2. 竞品到底怎么做、能借鉴什么

以下为截至 2026-11-10 官方公开页面的规则，不是本机逐账号实测。不同地区、版本与实验可能不同。详细来源与证据限制见[研究文档](COMMUNITY-MECHANISMS-RESEARCH.md)。

| 产品/机制 | 已核实的门槛或中断规则 | 对本方案的启发 |
|---|---|---|
| [TikTok Streaks](https://support.tiktok.com/en/using-tiktok/messaging-and-notifications/streaks?invalid_lang=pl) | 连续互发消息 3 天出现徽章；当日没互动先变淡，变淡后再过 24 小时无互动则消失；结束后 48 小时内可能恢复，每月次数有限 | 快速形成双人可见反馈，设置变淡与补救窗口；TikTok 规则不能直接称为中国抖音规则 |
| [Snapchat Streaks](https://help.snapchat.com/hc/en-us/articles/7012394193684-How-do-Streaks-work-and-when-do-they-expire) | 双方每天互发照片/视频维持，超过一天有人未发送会丢失；公开页不把起火精确门槛写成统一 3 天 | 火花属于两个人共同维持的状态；健身不照搬每天训练的频率 |
| [Duolingo 连续挑战](https://blog.duolingo.com/tips-for-maintaining-streak/)与[练友机制](https://blog.duolingo.com/product-lessons-friend-streak/) | 官方文章介绍过 7/14/30 天挑战；Friend Streak 围绕共同坚持与首次邀请设计 | 首周、两周、月度可作为早期目标；这些不是今天所有账号统一的等级权益表 |
| [Strava Streaks](https://support.strava.com/en-us/articles/15401580-streaks-on-strava) | 每个周一至周日有一次至少 60 秒活动维持周连续；整周没有则结束，可通过补传该周已有活动修复 | 运动频率可以按周，不能直接套每日聊天的断签规则 |
| [Nike Run Club 等级](https://www.nike.com/help/a/nrc-run-level/nrc-settings) | 按累计距离分级，如 50/250/1000 公里等边界 | 长期身份可以按累计投入积累，不需要与当前连续状态绑定 |
| [Apple Watch 活动圆环](https://support.apple.com/en-gb/guide/watch/apd29b30023c/26/watchos/26) | 可按星期调整目标；可暂停最多 90 天而不打断奖励连续记录 | 运动产品允许休整，不必靠逼迫每天训练保留身份 |

结论属于本项目的设计推断：**早期 3/7/14/30 天分段反馈、后期按季度/半年/年度承载身份；关系火花采用较短互动窗口，运动状态采用较长运动窗口。** 这些资料没有证明 TrainMind 应使用某个唯一最佳天数，更没有证明某套数字一定提高留存。

QQ、国内抖音与 Keep 的现行完整升级/熄火表，本轮未获得足以核对的官方材料，不将二手攻略写成确定规则。尤其不能把 Keep 课程难度 K1–K5 当成社区用户等级。

## 3. 三件事分开计算，界面只用一套“练友火花”

### 3.1 长期等级：累计有效打卡日

等级建议改为**累计有效打卡日**，不再要求某一段连续达到全部等级。连续打卡 7/14/30 天仍可作为可选挑战与纪念章，但不控制全部长期权益。

| 当天行为 | 累计等级日 | 训练日 | 双人火花共同活跃日 |
|---|---|---|---|
| 完成有效训练 | 当天 +1 | 当天 +1 | 不自动增加，需有双方互动 |
| 主动记录恢复状态 | 当天 +1 | 不增加 | 不自动增加 |
| 双方交流训练/恢复，或确认共同训练 | 不自动增加 | 不增加，训练事实另算 | 满足规则时当天 +1 |
| 只登录、浏览、点赞、购买、系统自动消息 | 不增加 | 不增加 | 不增加 |

同一账号同一自然日最多贡献 1 个等级日、1 个训练日；同一对练友同日最多贡献 1 个共同活跃日。训练与恢复同日记录合并，不能重复获得天数。

有效训练：服务端记录的 completed 会话，且至少有一条已确认完成的组记录，排除预览、空跑、demo 与测试来源。它代表平台完成记录，不声称验证真实身体活动；不能仅信客户端传 human。

恢复日只需主动记录简短恢复状态，不强制运动、照片或长文，精力等具体状态默认私密。单靠恢复也可积累表达等级；陌生联系另外要求当前支持模式下的有效运动记录，见第 4 节。不同运动的有效日定义需分别适配，不能永久要求所有人都有力量训练组记录。手写平台外训练首版作为自述内容，不自动算升级。

不因一次中断扣等级。来源撤销、确认作弊或用户要求连同成就删除时可以重算，记录理由并可申诉。付费、消费和群发内容不能买天数。

### 3.2 近期运动状态：几天不练怎么算

建议按**距离最近一次有效训练之后，完整结束但没有训练的自然日数量**判断；当天未结束不提前算缺席。它是状态，不是新一套火花等级。

| 完整无训练日数量 | 本人看到的状态 | 权益与关系 |
|---:|---|---|
| 0–3 天 | 最近在练 | 不受影响，正常训练间隔 |
| 4–6 天 | 休整中 | 不降级，不中断聊天，不要求补练 |
| 达到 7 天 | 暂歇；不再展示“近期在练” | 累计等级、朋友、共同历史保留 |
| 再次完成一场有效训练 | 恢复“最近在练” | 当天按原规则记 1 个有效日，不追回空缺日 |

**回答“几天不练取消”**：本稿建议 **7 个完整自然日没有训练，取消个人的“近期在练”状态**；不因此熄灭两个人的互动火花。7 天是参考运动按周发生的初始设计值，不是 Strava 的原规则——Strava 按周一至周日，本方案按滚动空缺日。

例：11 月 2 日训练后，11 月 3–9 日都没有训练，则 11 月 10 日 00:00 变为暂歇；若 11 月 9 日内训练，则未到 7 个完整空缺日。只做恢复打卡可以累计身份，但不能让“近期在练”永远亮着。

用户可主动设置“休整到某日”（首版最多 30 天，建议参数），期间显示自选休整，不显示训练中，也不增加虚假的训练日。休整不阻止聊天和小圈参与。7 天状态不是训练处方，个人安排低频或因不适休息，不受权益惩罚。

### 3.3 练友火花：两个人有没有持续来往

只在已双向接受的练友之间启用，默认双方可见；不在陌生人档案展示与谁互动、何时互动，也不提示“是谁拖累了火花”。

**共同活跃日**满足以下任一：

- 双方在练友会话中都有主动回复；一方群发或系统自动消息不算。
- 一方向对方分享训练/恢复卡，另一方主动回复该卡。
- 双方各自确认同一次共同训练活动；同一次活动只能贡献活动发生日的一次，不因两人隔天补反馈多算。

不设置消息条数冲刺任务；重复灌水、自动脚本不作为有效互动。群里两个人各自发言不自动视作双人往来，也不要求 AI 裁决聊天有没有“足够深度”。

| 阶段 | 建议规则 | 这样设计的原因 |
|---|---|---|
| 初次点亮 | 7 天内出现 3 个不同的共同活跃日 | 借鉴 TikTok 的早期 3 天反馈，改为一周内 3 天以适应健身交往；这是本项目改造，不是竞品原规则 |
| 正常维持 | 最近共同活跃之后，0–1 个完整空缺日 | 不要求训练，也不要求每天互发多条 |
| 变淡 | 2 个完整自然日没有共同活跃 | 给一次明确的回归机会，不发公开责备 |
| 熄灭 | 3 个完整自然日没有共同活跃，次日 00:00 熄灭 | 比每日聊天火花更宽；3 天仍是待测试起点 |
| 短期恢复 | 熄灭后 48 小时内，双方确认恢复且产生一个新的共同活跃日；每对关系每自然月最多 1 次免费恢复 | 保留补救窗口，不能单方面或付费强迫另一人续上 |
| 超出恢复窗口 | 从熄灭后的新互动开始，重新积累一周内 3 个共同活跃日点亮新一轮 | 历史共同天数、照片、活动与关系仍保留 |

**时间例子**：11 月 2 日最后一次共同活跃，3 日为空缺第 1 天；5 日 00:00 因 3、4 两天空缺显示变淡；6 日 00:00 因 3、4、5 三天空缺熄灭；可恢复窗口到 8 日 00:00，不把“3 天”含糊写成滚动 72 小时。

火花数字标注 **“本轮共同活跃 N 天”**，只累加真实共同活跃日，不把中间宽限日算进去，更不能写成“连续训练 N 天”。熄灭后保留“历史共同活跃 X 天”；免费恢复沿用上轮真实计数，加上本次真实互动日，空缺日不补造。

**长久的朋友不会因火花熄灭而被删除、禁聊或失去共同相册。** 火花的作用是让关系被看见、方便回来，长期留下来的理由仍应是这段关系本身。

可恢复窗口中的新互动先记为待恢复活动；恢复成功时归入原轮，超过窗口未恢复则归入新轮，按关系+日期去重。不能重新使用熄灭前的活跃日凑出新一轮，也不能把同一天同时算入两轮。同一轮最多恢复一次，重复点击不重复加数；月度额度按恢复成功日所在自然月扣减。屏蔽或解除关系后不继续计算；重新建立关系不自动恢复旧火花。

### 3.4 时间、补录和状态归属

首版统一按 Asia/Shanghai 自然日计算，等级日、运动空缺日和火花空缺日均用服务端时钟，规则版本化。账号加入日期记第 1 日，达到累计 7 日的第 7 个自然日完成打卡后即可判断联系资格；不混用 168 小时。14 日约练资格同理。一周内 3 个共同活跃日按含今天在内的最近 7 个自然日计算。跨午夜训练按完成日，聊天按实际服务端事件日；约练按活动发生日且需双方确认，不能重复计。状态计数分开，不把恢复、评论或关系反馈写成训练完成。

既有 D23 训练统计按服务器本地时区；社区固定业务时区，在上海部署时一致，跨时区发布前需统一，不静默重写历史。没有明确来源的旧记录不推算连续和共同关系；不自由补签买等级。平台故障可按已存在事件修复，离线训练联网确认后由明确的同步规则处理。

记录删除须提示是否保留成就凭据；选择一并删除则重算资格，但朋友不会因为个人训练数据删除自动消失。涉及双方聊天/共同相册与必要交易记录的保留、删除与导出需要分别说明。

## 4. 等级范围与权益：前期密，后期按时间跨度

**建议起点：累计 3 / 7 / 14 / 30 / 90 / 180 / 365 个有效打卡日。** 这是长期等级，实际经过的日历天数可能更长。没有证据证明恰好这些数字最优；首轮要重点验证第 7 天能否帮助建立关系，第 14 天是否值得扩展权限。

| 等级 | 累计有效日 | 用户阶段与主要权益 | 动态上限/日 | 陌生招呼/日 | 指定商品目标优惠* |
|---|---:|---|---:|---:|---|
| L0 初来 | 0 | 第一天就能进入运营维护的 4–8 人新手圈、分享训练卡并交流 | 1 | 0 | 公开活动价 |
| L1 起步 | 3 | 初次身份徽章，更多图文空间；可和已有练友点亮火花 | 2 | 0 | 公开活动价 |
| L2 常来 | 7 | 满足联系资格后，开始少量陌生招呼与双向聊天 | 3 | 1 | 9.8 折 |
| L3 同行 | 14 | 扩大招呼额度，申请/发起 2–4 人免费约练，同时最多 1 场 | 4 | 3 | 9.7 折 |
| L4 稳定 | 30 | 60 秒视频、系列记录；可申请创建练友圈，同时最多 2 场约练 | 5 | 5 | 9.5 折 |
| L5 深耕 | 90 | 季度里程碑、圈子共创、同时最多 3 场约练 | 8 | 5 | 9.3 折 |
| L6 长跑 | 180 | 半年身份、成长合集、合作活动申请资格 | 10 | 5 | 9 折 |
| L7 同行一年 | 365 | 365 日投入身份、年度回顾、社区共创申请；之后按周年纪念 | 12 | 5 | 9 折 + 限额活动权益 |

\* 优惠依赖真实商家、指定商品、库存和月度成本上限，不是全站可兑现承诺；更高级不意味着无限便宜。商品条件相同时自动选最优价。等级不自动授予专业或组织者资质。

### 4.1 每个时间节点为什么放在这里

- **3 日**：给新用户一次早期反馈；灵感来自社交产品的快速点亮机制，不声称是习惯已经形成。
- **7 日**：一周能遇到多次不同训练/休息场景；参考 Duolingo 文章中的首周目标，尝试把首次陌生联系前移，避免关系形成等两周。
- **14 日**：两周后更容易看到是否持续参与；保留用户提出的两周作为重要节点，但用于扩展约练，而非所有交往的起点。
- **30 日**：月度成长回顾，增加表达和圈子能力；参考已有产品的月度挑战节奏，不引用不存在的行业最优值。
- **90/180/365 日**：季度、半年、年度的可理解时间尺度，让长期用户仍有共同仪式；是产品判断，不是从 NRC 公里数换算成天数。
- 大档之间可在 60/100 日等提供轻量纪念卡，不额外创造一套权限等级。首版不用为了每天升级堆出几十级。

### 4.2 资格、连续徽章与配额

陌生联系建议条件：账号加入至少 7 个自然日、累计有效打卡至少 7 日、至少 2 个不同日期的有效训练日，以及账号验证、成年和正常账号状态。受对方接收设置约束。这里的训练日是当前已支持模式的记录；未来支持步行、跑步等项目后，按各项目有效运动日扩展，不要求所有人完成力量训练。当前未覆盖的项目不伪称已可计入。若 7 日全为恢复，保留表达权益，联系资格暂不满足，不引导加练。

用户发起/申请线下约练需加入至少 14 日、累计打卡 14 日，并满足上述联系资格。第 1 天可参与平台组织的新手圈与运营组织的受控活动，不以此绕过私人资料读取和陌生私信资格。

**这主动修订了 v0.1 的“两周才开放滴滴”建议，理由是先服务第一周的关系形成。** 7 日少量联系与 14 日才开放联系应在试点比较，不能声称 7 日已被证明更好。此变更是建议，未当作用户已确认的新裁决。

连续 7/14/30 天挑战只发连续纪念章；漏一天结束本轮连续挑战，但不扣累计等级、取消既有关系或扩大优惠。不要在同一个头像旁同时塞满三种相似火焰，公开身份优先等级与累计投入，双人会话内展示练友火花。

额度由服务端控制，成功发布计数；删除不返额度，技术失败不扣，重试幂等。私密记录不限发布额度。等级上升可以增加内容空间和消费权益，但陌生招呼在 5 次/日封顶，待回应总量仍受第 6 节限制；运营验证后可调，不出售触达权限。

## 5. 社区内容：先让人认识彼此，再扩展形式

### 5.1 首版内容类型

| 类型 | 用户要表达什么 | 产品提供什么 |
|---|---|---|
| 生活与运动照片 | 我喜欢现在的状态、想分享好看的照片或生活片段 | 自愿发布的图文/影像，不强制附训练数据、教学或前后对比 |
| 训练打卡 | 今天练了、练后感觉如何 | 可编辑卡片：坚持天数、课程阶段、自选感受；次数来源严格沿用原记录 |
| 恢复日记 | 今天不练，也在照顾自己 | 简短恢复卡，不公开具体健康状态 |
| 成长记录 | 一段时间以来的变化 | 周/月里程碑、自选照片，发布前预览与隐私确认 |
| 找练友 | 我什么时候、在哪里附近、想练什么 | 结构化约练卡，避免只发“有没有人” |
| 经验与问题 | 新手困惑、器械体验、练后分享 | 话题标签；个人经验与平台指导分开展示 |

发布图片或视频是独立的主动上传：不得把现有本地影像留档自动上传社区。本人相册中出现他人时提供裁剪/遮挡入口和发布提醒。

照片的审美价值、训练经历的共鸣、想获得的信息与向往的生活方式，都是关注与回访的合理来源。内容可以好看、愉快、真实或有启发；平台不要求每条内容都具有教学意义或直接促进一次训练。

### 5.2 信息流与圈子

首版推荐页签：“关注 / 同路人 / 发现”。关注是第一天开放的独立单向关系；同路人优先比较当前计划结构、主动选择的目标与阶段；发现在主题、创作者和同城活动之间展开，附近约练从发现的同城入口进入。

同路人先回答“练的事是否相近”，实际约练再考虑自愿填写的时段、片区和愿意怎样交流。不同城市也能是线上同路人。没有计划或比较依据不足时，按主动选择的项目/目标冷启动并说明来源；不输出虚假的精确相似度，不从健康限制推导病史标签。

- 排序先看内容相关性、时效、重复度和内容质量，等级只是身份，不自动垄断曝光。
- 明确给新用户与小体量创作者探索位置，避免高等级用户靠额度淹没信息流。
- 首版不设身材榜、训练量榜或发帖数量榜。可以提供“本周第一次来”“坚持两周”等共同话题。
- 关注不等于允许私信。评论区不提供绕过屏蔽的 @、回复或联系方式轰炸。
- 练友圈按场地/时间/项目建立，如“周二周四晚·徐汇力量训练”；首版普通圈不承接付费教学和推销。

### 5.3 固定练友圈：首版核心，而非等社区热闹后再做

首版由运营在真实用户中建立 **4–8 人固定圈**，结合当前可比较计划与主动选择的训练阶段、常用时段、城市/场地分组；计划仅是候选信号，首版仍由运营核对和维护。加入自愿；不把体重或疾病作为公开匹配标签，也不展示精确出勤轨迹。

- 第一天提供“和同阶段的人一起开始”，用户选择圈子；48 小时内争取有人回应，不能用假用户制造热闹。
- 同一圈连续运作至少 4 周，优先重复遇到同一批人；用户不合适可退出或换圈，不每天重新随机分配。
- 每周展示成员愿意分享的计划时间与打卡卡片，给下一次一起练提供共同话题。
- 每个人选择自己的周目标，不把圈总训练量分摊成强制任务；生病休息不拖累别人、不公开指责。
- 每周形成一张“这一周我们做了什么”的共同回顾；合照、个人卡片、姓名展示均尊重各自可见范围。
- 圈内公开交流从第一天开放，私聊需要双方确认；同圈身份不能绕过陌生招呼资格和屏蔽。
- 新用户不愿加圈仍可正常训练、浏览、分享，不被强制绑定陌生人。

**首个运营目标**：让用户在第一周至少认识一个愿意再次回应的人。具体比率待建立基线，不能用群里人数或全站消息数冒充。

### 5.4 共同周目标与关系记忆

参考 Duolingo Friends Quests 的共同任务思路，首版做轻量共同周计划：双方各自设定合适频率，愿意时把当周进度分享给同一位练友，周末生成共同回顾。无需同时在线或完成相同动作，不按双方中更强的人加剂量。

会话中保留：已同意的下次训练安排、共同活动卡、双方确认的共同训练次数、获准保存的共同照片、愿意收藏的鼓励。小圈也有自己的回顾页。用户回来首先能看到这些人与事，不是先被要求续火花或领优惠。

共同计划需双方接受，不能替好友设置目标；鼓励入口不变成代发催练。周回顾不公布“谁导致失败”，也不拿陌生私信数量评贡献。

### 5.5 关注与创作者：独立于同路匹配的关系

关注从第一天开放，公开内容可单向关注，私密账号按其规则批准；不需等级、不要求计划相似、不自动获得私聊权限。关注流默认按时间看到已关注者有权限发布的内容，推荐另外标识；可取消关注、移除粉丝、屏蔽与关闭通知。

创作者可以因运动生活、迎接新人、长期陪伴、个人成长和专业知识获得认同，不要求拥有最显著的身材或最强运动表现。等级、粉丝与专业资质分别表达；商业合作标识清楚，圈子管理和专业认证另行核实。

社区分发同时照顾创作者的持续表达、普通人的回应与固定圈的来往。不能只优化粉丝数和时长，让大号挤掉用户找到同伴的机会。个人经历与专业建议清晰区分，不用身材、年龄、残障或伤病羞辱用户。

### 5.6 多种运动、同一种生活追求

支持走路、跑步、力量、灵活性活动、日常恢复等不同运动生活的交流；实际记录与训练支持按能力逐步扩展，不假装当前产品已提供所有运动与医疗康复服务。用户自愿分享康复历程可以得到理解，不由系统自动给病友配对或公开敏感原因。

面向更广运动人群时，资格和等级需要通用的有效运动日与来源口径，不能把力量组数作为唯一门票。浏览、关注、分享、圈内参与先保持包容；陌生联系和约练仍受账号、双方意愿与当前支持活动口径约束。详见[同路人与关注设计](COMMUNITY-PATHMATES-AND-CREATORS.md)。

## 6. “滴滴”：一次有上下文的邀请

### 6.1 资格与双方选择

“滴滴”是一个可接受、可忽略的招呼请求，不是直接推送进私人聊天。

发送条件：满足第 4.2 节的 7 日联系资格；账号通过实际账号验证；首版声明成年；账号状态正常；额度充足；双方未拉黑。接收条件：对方已满足同样的联系资格，并主动开启“接收练友招呼”。公开资料和附近发现是另外两个独立开关，默认均不因升级自动开启。

默认接收上限为每天 10 个新请求，可调低或关闭。达到上限时暂停新投递；不向发送者透露对方是否拒绝、何时在线或收到多少请求。

### 6.2 发送流程

1. 在动态、同路人或附近页看到对方的公开档案。
2. 点“滴滴”，先看到共同点，例如“都选了晚间训练 · 都在同一个片区”。
3. 选择招呼意图：“想找固定练友 / 想一起练这一次 / 想交流器械”，可补充最多 80 字。
4. 未建立关系前不发送图片、链接、电话或外部账号；不支持批量复制发送。
5. 确认发送并扣除 1 次额度。显示“已发出，等对方愿意回应”，不显示已读。
6. 对方收到请求卡，可接受、忽略、拒绝、拉黑或举报，不接受也不必解释。
7. 接受后建立双向练友关系，开启文字聊天与约练卡；图片等能力按后续版本开放。

### 6.3 请求与关系状态

`未发送 → 待回应 → 已接受 / 已拒绝 / 已过期 / 已撤回`；关系另有 `正常 / 已解除 / 已屏蔽` 状态。

- 请求 7 天未回应自动过期；同一对账号只允许一个待回应请求，未回应不允许追加消息。
- 拒绝或过期后 30 天内不能再次向同一人发起；撤回同样不返还额度、不绕过冷却。
- 同时待回应请求最多 10 个，即使每日额度更高也受总量约束。
- 不暴露拒绝原因或精确拒绝时间，发送方统一看到“当前无法继续联系”。
- 拉黑立即阻断请求、聊天、推荐、约练申请和通过同一活动绕行接触；已有活动提供退出与运营处理入口。
- 解除关系后不能继续发消息，也不能通过取消关注重新触发新请求。
- 新升级、异常批量行为或申诉期间可降低陌生触达额度，规则不能因等级高而豁免。

### 6.4 熟人路径

新用户可以通过双方主动交换的邀请码/二维码添加已认识的人，双方确认后联系，无需等待等级天数。邀请码不出现在附近页，不允许批量搜索手机号或通讯录。该路径只服务已认识的人，不能成为陌生发现绕过门槛的入口。

## 7. 附近约练：匹配能一起练的人

### 7.1 附近发现

对方开启附近可见，才有机会出现在附近页。用户可以选大致片区，无需始终开启定位；拒绝定位仍能使用内容与同城手动筛选。

候选排序优先考虑：同场地或同片区、时间窗口重合、训练项目、是否接受新手，再考虑距离档位。不能仅按颜值、性别或消费能力排序。

公开卡片示例：

> 小舟 · 同行者 · 累计打卡 16 天
> 徐汇片区 · 工作日 19:00–21:00 · 力量训练
> 接受新手 / 倾向小团体 / 想找长期练友

不展示精确坐标、实时位置、实时在线状态、固定出勤轨迹或“刚刚离开健身房”。距离采用较粗分档（如同片区、邻近片区、同城），首版不提供可反复刷新逼近的米级距离。精确场地是活动信息，不等于某人的当前位置。

### 7.2 发起约练卡

首版支持公共健身房、公园等公开场地的免费 2–4 人约练，不支持私人住址或私下收费教学。

必填字段：标题、日期、开始/结束时间、场地、训练项目、人数、是否接受新手、预计自付场馆费用、加入方式。费用即使为 0 也写清楚；平台首版不代收约练费用。

建议标题：“周四 19:30 · XX 健身房 · 力量训练找 1 位练友”。同场不强制同剂量，每个人沿用自己的训练安排。

### 7.3 完整流程

| 步骤 | 产品行为 |
|---|---|
| 发起 | 校验第 4.2 节的 14 日约练资格与同时开放活动数，公开活动卡等待申请 |
| 申请 | 申请者同样具备第 4.2 节的 14 日约练资格；附可参加时间与一句说明；每天最多提交 3 次新申请，不与滴滴互相绕额度 |
| 确认 | 发起者接受后占位，数据库原子限制名额；未获同意不建立聊天关系 |
| 联系 | 为已确认成员开放本次活动文字会话；参加活动不自动互加练友，不公开手机号 |
| 变更 | 时间、地点、费用等关键变更需成员重新确认；拒绝变更可退出，不记失约 |
| 见面 | 在约定公共地点集合，用户可将活动卡通过系统分享发给自己的可信联系人，不自动发送 |
| 结束 | 双方可各自确认“见到了 / 没去成 / 对方未到”；默认 48 小时内完成反馈 |
| 再练 | 双方主动选择“愿意再一起练”，可互加练友或发起下一场，不自动生成重复约练 |

同一人同一时段不能确认多场重叠约练；每人最多 3 个待处理申请。活动卡可取消，取消立即通知已确认成员并关闭新申请；未到开始时间的退出不公开羞辱。重复迟到/失约只在有上下文且可申诉时限制新的约练资格。

### 7.4 履约与纠纷

首次评价优先用结构化反馈，避免把约练变成外貌评分。等级不替代履约记录，两者分别展示。单方面“对方没来”的反馈不直接形成公开失约结论；有冲突时标待处理，由运营核查，严重行为可以先暂停新联系再处理。

双方确认见面只能作为“双方反馈一致”的约练记录，不宣称平台已定位验证。不得为了证明赴约强制上传定位、自拍或两个人的合影。

活动结束 7 天后关闭临时会话的新消息；已成为练友者继续在双方聊天里联系。退出社区、拉黑或举报的入口始终可用。保留证据的具体期限需要在上线规则中确定，不无限保留位置与聊天。

## 8. 优惠权益：给坚持一个实际回报

### 8.1 先做哪些权益

优先考虑运动服饰、小器械、合作健身房体验/次卡、公开团体活动。首版优先定额或封顶券，避免一开始建设全品类商城。品牌与场馆用独立的合作身份展示，不能伪装成高等级普通用户。

三类权益可以并行：

- **长期身份权益**：头像框、徽章、里程碑主页，达成后持续保留。
- **月度消费权益**：按已获得等级领取指定优惠，每账号每月 1 张，具体商品与上限明确。
- **限额活动权益**：合作场馆体验或社区活动名额，采用明确报名/抽签规则，不承诺人人有库存。

### 8.2 折扣约束与示例

每个商品必须分别配置适用等级、有效期、库存、最高优惠金额、是否可叠加、承担补贴方、退款处理与最低成交价。同品同条件比较时，高等级应不差于低等级；结算自动选最优可用方案，避免会员价反而更贵。

建议折扣只覆盖参与的 SKU/服务，首版每月补贴预算按用户封顶，例如 20 元。这是测算参数，不是当前可领取权益。

示例：标价 199 元，供货成本 140 元，履约与支付等变动成本合计 15 元。9 折成交 179.10 元，订单贡献为 `179.10 − 140 − 15 = 24.10 元`。若要求最低贡献 20 元、单用户月补贴上限 20 元，本单优惠 19.90 元才在这组假设下成立。若广告、退货或其他实际成本尚未计入，需纳入后重新算，不能把该示例当成实际利润。

**购物不是升级任务**：没有消费也能升到最高等级。下单不会点亮打卡日，消费金额不会增加陌生人接触额度。

### 8.3 券的状态与核销

`可领取 → 已领取 → 已锁定订单 → 已核销 / 已过期 / 已作废`。

同一账号、同一权益周期只能领取一次，重复点击幂等。退款不产生第二份补贴：规则允许时归还原券或原周期领取状态，不能凭退单刷券。若采用商家侧核销，使用短时一次性码及商家确认回执，不使用可无限传播的公共优惠码。

不在社区首版直接上线完整商城。若试点期没有明确的合作商家、售后责任和核销能力，只展示权益说明；实际领券要等真实供给可兑现。

## 10. 使用旅程：第一周就开始积累关系

小舟第一天完成居家训练，选择加入一个晚间新手圈。当天有人回应她的训练卡，接下来几次她再次遇到同一批人，不必每天从陌生推荐里重新找人。

她训练日自动打卡，休息日愿意时记录恢复。累计第 3 日获得起步徽章。到账号加入与累计打卡均满 7 日、已有至少 2 个训练日时，她可以每天发 1 次陌生招呼。她邀请同片区、时段合适的阿远，阿远主动接受。

他们在一周里有 3 个不同的共同活跃日，练友火花点亮；火花表达两个人的来往，和小舟哪天举铁无直接关系。第 14 日满足约练资格后，两人约周四在公共健身房见，各自照自己的训练计划练。

后续小舟工作忙，7 个完整自然日没训练，个人状态改成暂歇；期间仍和阿远交流，练友火花可以继续。再后来两人 3 个完整日没互动，火花熄灭，但朋友、共同回顾、照片和下一次约练不删除。双方可以在恢复窗口内一起续上，也可以以后开始新一轮。

小舟回来首先看到熟悉的人和他们做过的事。等级继续按已记录的有效日累计，不需要重复证明自己“有资格拥有朋友”。关系累积与可共同参与的事情，才是这一版优先验证的留存来源。

## 11. 防刷、内容治理和位置控制

这些能力随发布、陌生人联系和约练一起交付，不能靠高等级天然可信来替代。

| 风险 | 首版处理 |
|---|---|
| 只刷恢复、伪造训练、批量账号 | 7 日联系资格含 2 个训练日，14 日后开放用户约练；来源可追溯；账号验证与反刷；异常可人工复核，不声称能验证运动真实性 |
| 高等级群发骚扰 | 双方选择、每日与待回应总量限制、同人冷却、屏蔽举报、处罚优先于等级 |
| 位置被反复探测 | 附近默认关闭，粗片区，不提供可枚举精确距离；不展示固定实时行踪 |
| 新手被排除、身材焦虑 | 第一天开放内容互动；等级不统治推荐；不按体重、颜值或训练量排榜 |
| 内容/照片侵权与广告 | 发布审核、举报、申诉、处理记录；商业合作独立标识；训练影像不自动上传 |
| 私下收费、虚假教练 | 首版约练限定免费同伴活动；等级不是教练认证；商业服务走后续独立流程 |
| 线下骚扰与失约 | 公共场地、小人数、关键变更重确认、活动内屏蔽举报、纠纷处理；不靠免责声明代替运营 |
| 优惠倒卖与反复核销 | 账号绑定、短时一次性码、领取/核销幂等、退款规则与补贴封顶 |

首版陌生联系与线下约练仅面向 18 岁及以上用户，作为试点产品范围。年龄与身份核验方案、内容处理机制、数据使用与商家条款需在对外发布前落实，本文不是法律结论。

用户应能分别控制：档案是否公开、内容可见范围、是否附近可见、是否接收招呼、是否允许被推荐、通知设置。关闭附近后，从发现结果及时移除，并清理缓存；不要求删除整个账号才能退出社交。

没有站内举报、处置和申诉能力时，不开放陌生人联系和约练。运营需有可执行的严重事件响应机制；试点有人值守，避免只是放一个无人处理的按钮。

## 12. 与现有系统的衔接及数据边界

当前项目已有课程、训练完成记录、打卡日历、关系进度、导出/删除与本地影像方向，但没有完整的多人社区系统。

**现有训练者 ID 切换与请求中携带 `userId` 的方式不能直接作为社区账号体系。** 社区发布与读取私人消息必须先建立服务端认证、资源归属校验与账号恢复。请求中的发帖人、收件人权限和等级不能由客户端自报。原有演示入口与真实账号域需隔离。

建议新增的数据概念（用于范围估算，非最终数据库设计）：

| 概念 | 最少需要记录 | 主要约束 |
|---|---|---|
| 社区档案 | 账号、昵称、公开标签、可见性开关、年龄范围状态 | 用户资料与训练原始记录分开 |
| 计划推荐摘要 | 当前计划版本、可比较运动结构、主动标签、推荐同意与来源 | 原始健康与聊天记录不进入摘要，关闭后停用 |
| 关注与创作者 | 单向关系、私密关注申请、内容主题、资质与合作标识 | 关注不等于练友/私聊，粉丝不等于认证 |
| 每日打卡 | 账号、业务日期、训练/恢复类型、来源事件、时区 | 账号+日期唯一，服务端计算 |
| 等级与运动状态 | 累计有效日、训练日、等级、7 日联系/14 日约练资格、最近训练与休整 | 与个人连续挑战分开，服务端重算 |
| 练友火花 | 双方、真实共同活跃日期、轮次、状态、熄灭时间、免费恢复次数 | 与训练日分开；空缺日不造数 |
| 固定圈与共同周目标 | 自愿加入、成员可见范围、个人目标、双方接受、回顾 | 退出/屏蔽可执行，不自动公开健康和轨迹 |
| 内容与媒体 | 作者、正文、可见范围、来源卡片快照、审核状态 | 私密媒体必须再次确认才能公开 |
| 招呼与练友关系 | 双方、请求状态、冷却、接受时间、屏蔽状态 | 双方关系与发送额度原子校验 |
| 约练 | 发起者、地点范围、时间、名额、申请与成员状态 | 防超员、防重叠、关键变更重确认 |
| 权益与券 | 规则版本、周期、领取、预算、核销、退款状态 | 同周期领取唯一，一次性核销 |
| 治理记录 | 举报、处理状态、限制原因、申诉 | 最小权限访问，不向被举报者泄露举报人 |

所有接口统一按服务端账号授权，私密档案、会话与活动成员必须校验读取权限。媒体直链不可绕过可见性；删除或撤回需连同预览、缓存与索引失效。位置数据不混入普通内容埋点。

训练卡只从现有事实生成：推定次数不变成“实测进步”，恢复打卡不变成课程完成，约练反馈不变成训练完成，社区等级不反向调整训练剂量。用户导出与删除要覆盖新增的公开内容、消息、约练和权益记录，并说明与他人共同内容及交易记录的处理方式。

## 13. 分期上线：先证明小圈能让人再次回来

### P0：固定圈与关系闭环

选择一个真实用户群或少量相邻场馆，小范围邀请参与。第一周就有可以回应的人，不虚构练友，不将所有社交入口封到两周以后。

必须交付：

- 账号认证、权限归属、主动加入与退出、隐私和可见性。
- 累计打卡、3/7/14/30 日早期等级，长期节点在规则中预留。
- 可解释的计划相似候选与主动标签冷启动；原始健康信息隔离，关闭与纠正可执行。
- 第一天开放关注/取消与关注流，公开/私密内容校验；支持持续发布的创作者及主题内容。
- 运营维护的 4–8 人固定圈、文字/训练卡交流、同一批人的共同周回顾。
- 7 日联系建议、双向练友关系、文字聊天、独立双人火花及免费恢复。
- 14 日用户小型约练、公共场地、确认/取消/反馈。
- 内容处置、屏蔽举报、申诉和数据导出/删除。
- 真实合作供给存在时才开放一种可核销优惠，不优先建设商城。

视频、自动分圈、大规模群聊与复杂商业货盘可以后置。小圈最初由运营配置并维护，不为了“自动化”而省略欢迎、回应和共同活动。

### P1：重复共同活动与长期身份

固定关系形成后，完善共同相册与年度回顾、圈子共创角色、视频成长记录、长期身份、合作权益。可测试双方主动的火花休整功能，休整时不亮活跃火花、不造活跃日；不直接照搬 Apple 的 90 日规则。

### P2：扩场地与城市

只有当单个圈子能产生持续往来、约练能复约、运营能处理问题，才扩展地理范围。不要用全国附近人数代替某个具体时段真能约到人的密度。

## 14. 用什么证明“关系成为壁垒”

**主指标：周稳定练友用户率。** 在本周有社区访问的用户中，至少有 1 位双方接受的练友，且两人在本周与前一周均有真实共同活跃的用户占比。火花宽限、补救本身不能把没有互动的关系计为稳定。

它需要与同批用户的 D7/D30/D90 留存、训练计划完成和圈内复访一起观察；不将高等级用户本来就更活跃误判为机制效果。

| 需要验证的环节 | 具体口径 |
|---|---|
| 第一周认识一个人 | 注册/加入社区 7 天内，在至少 2 个不同日期和同一真实用户有双向回应；不要求先互加好友 |
| 首次归属 | 自愿加入圈后 7/14 天，是否再次访问同一圈并与同一批人来往 |
| 同路价值 | 计划相似推荐相对仅用标签推荐，是否增加同一个人的重复回应与自愿练友；控制默认模板影响 |
| 关注价值 | 同一创作者跨周被主动回访、收藏和持续阅读，兼看普通人与固定圈获得回应 |
| 文化与包容 | 不同项目/阶段用户是否觉得有适合自己的内容与位置，纠正错误标签与身材羞辱 |
| 稳定关系 | 同一对练友连续两周有共同活跃，而非全站总消息数 |
| 周计划和共同回顾 | 双方接受、各自自愿分享进度、回看同一份共同回顾的比例 |
| 约练与复约 | 双方一致反馈见面；28 天内再次与同一人约练；只作反馈口径，不冒充定位验证 |
| 火花有无帮助 | 火花展示后真实关系次周继续率、恢复后是否仍有互动，不只看亮着的数量 |
| 长期沉淀 | 30/90 天仍有固定练友、熟悉小圈、未来约定和用户愿意保存的共同回顾 |
| 权益与商业 | 领券/核销、成本、退款，与关系和留存分开统计 |
| 体验与退出 | 屏蔽举报、无意义刷消息、通知关闭、圈退出、位置投诉和处理进度 |

### 单独验证关键数字

1. **联系门槛**：比较第 7 日少量开放与第 14 日才开放；都允许从第 1 天参与运营圈。看同一人重复回应与 D30 留存，并看骚扰率，不能只看请求数。
2. **火花容错**：先以 3 个完整空缺日熄灭为基线，再测试 2 日或 5 日。长了可能失去状态意义，短了可能造成无意义续火。哪一个更好必须看关系次周维持与退出数据。
3. **长期节点**：记录到 3/7/14/30 日各步流失与权益使用。90/180/365 日需要相应长的真实观察，不根据首月数据宣称已验证。
4. **增量贡献**：优先比较固定圈/共同周计划与仅打卡展示；火花和折扣作为后续独立变量，不把所有机制同时上线的变化全归功于火花。

固定圈存在互相影响，比较圈机制时按圈或独立批次分组；火花按练友关系或网络簇分组，避免同一个人同时承受互相冲突的过期规则。预先写明观察周期、主要指标与体验限制，不为追求显著性反复改指标。

首周、首月先收集基线与访谈，样本不足不承诺统计显著性。不采用“关停导出、关系断签后禁聊”制造离开成本；目标是用户愿意留下，而非无法离开。

## 15. 验收场景与边界

| 场景 | 预期 |
|---|---|
| 累计 14 日打卡，中间漏 2 日 | 等级到 L3；实际经过至少 16 日，不能展示连续 14 日 |
| 累计 7 日但只有恢复记录 | L2 表达权益；联系资格未满足；不引导多练补资格 |
| 加入 7 日、打卡 7 日、2 个训练日 | 可发 1 次陌生招呼/日；仍受对方设置和账号状态限制 |
| 同日多场训练/恢复/聊天 | 等级日最多 +1；训练日最多 +1；同一对练友共同活跃最多 +1 |
| 第一天进入新手圈 | 可正常圈内交流；不能借此读取私人资料或绕过陌生私信门槛 |
| 11 月 2 日训练，3–9 日未练 | 10 日 00:00 暂歇；等级不变；与好友持续交流则火花不受影响 |
| 11 月 2 日最后共同活跃，3–5 日无互动 | 5 日 00:00 变淡，6 日 00:00 熄灭，8 日 00:00 恢复窗口结束 |
| 一方发十条、另一方未回应 | 不新增共同活跃日，不靠单向消息延续火花 |
| 一周内 3 个非连续共同活跃日 | 点亮，显示本轮真实共同活跃 3 日，不叫连续 7 日 |
| 熄灭后 48 小时内只一方点恢复 | 不恢复；需双方确认与新的共同活跃，且本月有恢复额度 |
| 恢复成功 | 沿用上轮真实共同计数，加新活跃日；不补造空缺日 |
| 火花熄灭或运动暂歇 | 朋友、聊天、历史和下一次约定保留；不撤已得等级 |
| 取消/拉黑关系 | 不再计火花，停止消息与推荐，不通过同圈/活动绕过 |
| 两人抢最后一个名额 | 至多一人确认；关键时间地点变更需重确认 |
| 重复领券/核销与客户端伪造等级 | 幂等与授权由服务端校验，无重复权益、无冒用 |
| 关闭附近/退出社区/导出删除 | 独立执行对应范围，不被火花或圈子强制留住 |
| 双方训练安排不同 | 可以共同参与周目标，不增加任何一方训练剂量 |
| 同一默认模板覆盖很多人 | 不直接认定高相似/相同身体，检查有效计划与区分度 |
| 计划相似但用户不约练 | 可成为线上同路人，不开启私信或位置权限 |
| 换计划或关闭推荐 | 更新/停止候选，保留主动关注与已有朋友 |
| 第一天关注公开创作者 | 能看到公开内容，不需等级，不因此获得私聊或私密计划 |
| 高等级或粉丝多 | 不自动获得专业认证、组织者管理权 |
| 不同运动与恢复需求 | 基础社区参与不受项目歧视，具体计日与服务范围按实际支持说明 |

## 16. 仍需验证的建议值

| 项目 | v0.2 建议 | 证据与未决边界 |
|---|---|---|
| 等级 | 累计 3/7/14/30/90/180/365 日 | 早期短目标参考公开机制，长期跨度为本项目判断，不是行业标准 |
| 联系与约练 | 7 日少量联系、14 日扩展用户约练 | 为第一周关系形成而提出；与原 14 日联系方案比较 |
| 运动状态 | 7 个完整无训练日转暂歇 | 参考运动按周发生，不是连续训练处方 |
| 点亮练友火花 | 一周内 3 个共同活跃日 | 从社交 3 天反馈改造，放宽连续限制；待观察 |
| 火花变淡/熄灭 | 完整空缺 2/3 日 | 参考短反馈+宽限；3 日初值并无现成效果证明 |
| 免费恢复 | 48 小时、每对每月 1 次、双向确认 | 窗口借鉴社交产品；次数与双向条件为本方案建议 |
| 固定圈 | 4–8 人、同一圈至少 4 周 | 为重复遇见而选的运营起点，不称作最佳群规模 |
| 优惠 | 指定商品、等级递增、预算封顶 | 真实货盘核算后才对外承诺 |

用户已明确的是“社区要形成朋友关系与留存壁垒、用坚持形成身份并给社区和消费权益”；本表数字与累计/连续拆分是研究后的提案，不记录成用户已经批准。本文记录完整目标方案；本批已实现能力与后续范围以[实施记录](COMMUNITY-IMPLEMENTATION.md)为准，未完成部分不视为已上线。

### 同路人与创作者新增配置边界

计划相似度采用哪些特征、怎样归一化与区分默认模板，需离线案例和用户反馈后确定；本稿不拍定百分比门槛和权重。关注第一天开放属于本轮用户强调的核心方向；创作者分发与多运动记录的实际能力需据实现逐步验收。
