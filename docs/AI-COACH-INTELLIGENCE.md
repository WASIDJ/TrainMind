# TrainMind AI 教练 · 智能度评估与优化路线

> 这份文档回答两个问题:**我们的 AI 教练现在智能到什么程度**、**下一步怎么更聪明**。
> 判定标准不是技术堆料,而是"用户能不能感觉到"。
> 数据来源:`src/core.ts` / `narration.ts` / `progress.ts` / `perception.js` / `coach-runtime.ts`,以及真机验收记录。

最后更新:2026-11-06

## 0. 一句话结论

**现在是"会执行、会收着说话、会听你喊停"的教练,还不是"会读懂你"的教练。**
判断与剂量已经可靠(规则层),措辞不再掉链子(叙事层),**卡在感知与记忆的深度**。

## 1. 五层能力:现状与天花板

| 层 | 现在能做什么 | 天花板在哪 | 证据 |
|---|---|---|---|
| **L1 计划** | 一句话需求 → 选动作 → 定剂量;带历史("连续两次偏难,减一组") | 只看近期历史,不做周期化 | `core.ts`、真机计划页 |
| **L2 剂量与安全** | 升降档、Agency、安全门;**LLM 与感知永远不碰数字** | 单场自适应;跨场周期(减载周)未做 | `core.ts` 102 项测试 |
| **L3 措辞** | LLM 只改说法:≤30 字、组内禁问句、失败回退模板 | 语言已不是瓶颈 | `narration.ts` |
| **L4 记忆** | 近 7 天事实 + 关系阶段(一起练了 N 次/连续 N 周/多久没练) | **只记"练了什么",不记"你说过什么"** | `buildMemoryFacts`、`relationship` |
| **L5 感知与时机** | 静默观测:能量包络 → 呼吸变重/发力峰值/组内停顿;时机引擎(每组 ≤2 次、冷却) | 音频在嘈杂环境不可靠,**阈值从未校准** | `perception.js` |
| **L6 交互** | 全语音:开始/做完/暂停/下一组/跳过/喊停三段式 | 命令词识别率未在健身房验证 | `index.html` |

## 2. 智能分级(自评)

- **L0 播放器**:放视频、倒计时
- **L1 记录员**:记下你做了什么
- **L2 执行教练**:按计划推进,该降就降,出事会停 ← **我们现在稳稳在 L2**
- **L3 会读人的教练**:自己判断你撑到什么程度,**知道什么时候闭嘴** ← 感知校准后可到
- **L4 会为你改计划的教练**:因为你这两周都吃力,主动安排减载周

**当前定位:L2+**——有 L3 的骨架(感知/时机),但感知没校准、记忆还停在数字层。

## 3. 十个"用户能感觉到"的瞬间(拿这个验收)

| # | 瞬间 | 现状 |
|---|---|---|
| 1 | 我不说,它记得上次偏难 | ✅ |
| 2 | 它替我数,不问我"做了几次" | ✅(D17) |
| 3 | 我喘起来,它自己说"顶住" | ⚠️ 静默观测中,未开 |
| 4 | 我停 8 秒,它说"喘匀了再继续" | ⚠️ 同上 |
| 5 | 我说"累了",它先问是累还是不对劲,再推我一把 | ✅ |
| 6 | 我说"太重",下一组真的轻了(含组后补一句) | ✅ |
| 7 | 它知道我已连续三周没断 | ✅ |
| 8 | 它知道今天该练什么,不用我挑 | ⚠️ 半:器械/时长仍要选 |
| 9 | 它用一句人话说清"为什么这么排" | ✅(禁因果句式) |
| 10 | 它会主动来找我 | ❌ 只有应用内唤回 |

**2 个 ⚠️ 和 1 个 ❌,就是下一步的全部工作。**

## 4. 真实短板(不粉饰)

1. **感知没校准**:×1.6 / ×3 / 8 秒全是假设;健身房噪声下音频基本不可用(已被 owner 否决为触发器)
2. **记忆是数字不是内容**:它不知道你说过"膝盖有点紧"
3. **没有跨周计划能力**:不会因为你连续吃力就主动减载
4. **不会主动找你**:没有推送,只能等你打开
5. **训练中没有即时推理**:不会说"刚才第三组你塌腰了"(那需要摄像头或 IMU)

## 5. 优化路线(按"可感知价值 / 成本"排序)

### P0 · 感知校准(本周,零新硬件)
- 静默观测已上线:先收 2–3 场真实数据,算**误报率/漏报率**
- 达标阈值建议:<20% 误报才允许开口(`TRAINMIND_PERCEPTION_SPEAK=1`)
- 验证:同一场,人工标注"我真的吃力了" vs 系统事件时间线

### P1 · 记忆从"数字"升级到"原话"(1 周)
- 只存用户**主动说出**的短句(≤30 字),可看、可删
- 用途:下次计划与叙事引用("上次你说膝盖紧,这次不安排跳")
- 红线:不做语义画像、不做健康推断;用户可一键清空
- 验证:用户听到记忆句后是否纠正/惊讶(惊讶=记错了)

### P2 · 跨周计划(2 周)
- 数据已有:`weeklyVolume`(完成场次/组数)、失败率、疼痛事件
- 规则:连续 2 周完成率 <50% → 下一周自动减量;连续 3 周稳定完成 → 升一档
- 验证:A/B 两周,看完成率与"太累"反馈比例

### P3 · 主动触达(需要推送基础设施)
- 现在是应用内卡片;真推送要 Service Worker + Web Push 或原生壳
- 先定规则再上技术:什么时候值得叫醒一个人(≥3 天未练、且历史上有回归意愿)

### P4 · 动作质量(远)
- 摄像头姿态(opt-in)或手机 IMU;先做 `/imu-check` 对照实验再谈

## 6. 怎么知道"更智能了"——四个可埋点的指标

| 指标 | 定义 | 目标方向 |
|---|---|---|
| **无用插话率** | 教练开口后 5 秒内用户纠正/否定/无响应的比例 | ↓ |
| **完成率** | 开始 → 练完的场次比例 | ↑ |
| **澄清次数** | 每场因信息不足而追问的次数 | ↓(但不能牺牲正确性) |
| **记忆命中率** | 用户听到记忆句后没有纠正的比例 | ↑ |

**不埋点就无法证明变聪明了**,这是下一步必须补的。

## 7. 明确不做

1. **不做诊断**(不判断伤病、不给医学建议)
2. **不替用户决定重量**(只给退路与建议,决定权在人)
3. **不假装懂**:数据不足时说"我还不知道",而不是编一句
4. **不靠惩罚驱动**(不抄 streak 断签/联赛降级那一套)

## 附:这份判断的边界

- 以上"现状"以代码与测试为准,凡未在真机验证的都标了 ⚠️
- "智能"没有客观标尺,本文件的 L0–L4 是我们自己的定义,可被推翻
- 感知与 IMU 的可行性仍需真机数据,当前只有推断
