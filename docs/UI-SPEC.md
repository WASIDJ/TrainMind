# TrainMind UI 设计规范 v1.0

> 给设计 / AI 生成用的**唯一事实来源**。凡与本文冲突的设计稿，以本文为准；本文没写的，先问，不要自己补。
> 现状实现见 `public/index.html`（17 屏）；本规范是它的**下一代**，不是复刻。

最后更新：2026-11-06 · 适用版本：D17 之后

---

## 0. 五条不可违背的硬约束

设计稿违反任意一条即不合格，**不需要讨论审美**。

| # | 约束 | 为什么 | 反面例子（已发生） |
|---|---|---|---|
| **1** | **训练中手不离器械**：组内每一个操作都必须有语音等价；按钮只是兜底 | 手里拿着哑铃/杠铃 | 组内只有「完成本组」「暂停」两个按钮 |
| **2** | **少打扰**：教练只在两处提问——①整场结束 ②真的卡住时 | D17 | 每组做完问"累不累/正不正好" |
| **3** | **不惩罚**：不做 hearts、断签惩罚、排行榜降级 | 陪伴、不痛苦 | 抄 Duolingo 的 streak freeze / 联赛 |
| **4** | **进度只认真实数据**：不显示推断出来的完成度 | 信任 | 用"目标次数"冒充"你做了几次" |
| **5** | **一句话说清为什么**：任何剂量变化都要有可读的理由，且禁因果句式 | 透明推理 | "因为…所以…" |

## 1. 信息架构

```
底部主导航（4 项）
├─ 首页      —— 今天练什么 / 一句唤回 / 最近一次
├─ 计划      —— 课程章节地图 → 今日训练
├─ 记录      —— 列表 → 详情；进度（规律性/动作级）
└─ 我的      —— 训练档案 / 教练设置

训练流程（离开主导航，全屏）
计划确认 → [热身] → 组内 ⇄ 组间 → [放松] → 结算 → 问卷
                     ├─ 喊停追问（组内子状态）
                     ├─ 退路三选一（组间顶部卡片）
                     ├─ 疼痛（全屏安全态）
                     └─ 暂停（全屏）
```

## 3. 全局规则

### 3.1 语音优先

- **组内每个动作都有语音等价**：`开始` / `做完了` / `暂停` / `继续` / `下一组` / `跳过这组` / `换个动作` / `结束训练` / `再说一遍` / `累了` / `不行了`
- 界面必须显示**当前是否在听**（见 3.3），但不能喧宾夺主
- 语音失败不是死路：始终有可点的等价按钮

### 3.2 文案规则（硬）

- **组内一句话 ≤30 字**（喘着气听不了长句）
- **组内不许提问**（除"喊停追问"这一处）
- 数字用阿拉伯数字；不要"你应该"；不要因果句式
- 第二人称、短句、动词开头

### 3.3 语音状态要可见（6 态）

| 状态 | 界面表现 | 文案示例 |
|---|---|---|
| 正在听 | 麦克风点 + 呼吸动效 | 听着呢 |
| 说话中 | 波形 | 教练在说 |
| 处理中 | 细进度 | 正在理解… |
| 没听清 | 一次轻提示 | 没听清,再说一次 |
| 权限被拒 | 指引卡（含"如何开启"） | 麦克风没开 |
| 不可用 | 降级说明 | 这台设备用不了语音,点按钮也行 |

### 3.4 空态与错误态（每屏都要有）

- 没有计划 / 没有记录 / 没有课程：一句人话 + 一个明确出口
- 网络失败：**不要**弹 toast 了事，要说明"现在能做什么"（例如"先按原计划继续，稍后会自动补记"）
- 加载：骨架屏，不转圈

### 3.5 无障碍

- 所有可点元素 `focus-visible` 可见
- 尊重 `prefers-reduced-motion`（关闭呼吸动效）
- 语音状态用 `aria-live="polite"` 播报
- 触控目标 ≥44×44

## 4. 关键屏规格

### 4.1 首页 ★

**必须出现**
1. 今日入口：一句"今天练什么"（有课程则显示"第 N 周 · 章节 · 第 M 场"）
2. **一句唤回**（仅当久未训练时）：如"隔了 4 天，身体正好恢复"
3. 关系摘要（一行，不抢戏）："一起练了 9 次 · 连续 2 周"
4. 最近一次训练（一行，可点进详情）

**不要**：红点、未读数、连续签到天数（惩罚暗示）

**语音**：计划页可直接说"开始"

### 4.2 计划生成 ★

一次拿全四件事，默认值要合理，**不做多步问答**：

| 采集 | 控件 | 默认 |
|---|---|---|
| 时长 | 步进器 20/30/40/45 | 30 |
| 地点 | 在家 / 健身房 / 办公室 | 上次选择 |
| **器械** | 多选 chips：自重(默认) / 哑铃 / 弹力带 | 自重 |
| 目标 | 全身 / 下肢 / 上肢 / 恢复 | 全身 |
| 状态 | 状态良好 / 有点累 / 有不适 | 状态良好 |

> **器械必须由用户选**。我们出过一次"家里没哑铃却排了哑铃卧推"的事故。

出口：生成（主）/ 语音说一句需求（次）

### 4.3 计划确认 ★

- 时长 / 动作数 / 总组数 / 强度（四个数字）
- **教练一句理由**（≤30 字，禁因果句式）："连续两次偏难，这次少一组"
- 动作列表：名称 / 组×次 / 休息 / 一句要点（可展开）
- 每项可：上移 / 下移 / 替换 / 删除
- 主按钮：**开始训练**（语音也能触发）

### 4.4 课程章节地图 ★（Duolingo 逆向结论）

**结构**：`章（Unit）→ 周 → 节点（= 一场训练）`

```
┌ 第 1 章 · 起步 ────────────────┐
│ 这一章要拿下：建立动作模式        │
│                                  │
│  第1周  ●━━●━━◉━━○               │
│         完成 完成 今天 未到       │
│  第2周  ○━━○━━○                  │
│                                  │
│  ⛩ 关卡：本周末 · 综合场           │
└──────────────────────────────────┘
```

**规则**
- 节点状态只有三种：**已完成 / 今天这一场 / 未到**（**没有"失败"**）
- "已完成"只来自真实完成的场次（`ProgramCompletion`）
- 章末一个**关卡**：一场综合训练；通过条件 = 该章全部场次完成且无疼痛中断
- 关卡**不设失败**：没做完就是没做完，不给惩罚、不锁死下一章
- 章头必须有"这一章要拿下什么"（一句话）
- 进入方式：计划 tab 顶部一张"章节卡"（一行字 + 进度条），点开才是全图

**借鉴与不借鉴**（来自 `reverse-lab/duolingo-工作笔记.md`）
- 借：Unit 主题+徽记、明确通过条件、解锁语义、Explained 前置说明页
- **不借**：hearts、streak freeze、联赛升降级、付费修复

### 4.5 组内训练 ★（最重要的一屏）

**必须出现**
1. 动作名 + 第几组/共几组 + 目标（"7 次" 或 "9 分钟"）
2. **进度环/步点**（表示整场的进度，不表示做了几次——我们不数）
3. 教练一行提示（≤30 字）
4. **"正在听"的轻指示**（不是大麦克风，是一个呼吸点）
5. 完成通道（双）：**滑动完成** + 语音"做完了"
6. 暂停入口（语音优先，按钮兜底）

**绝不要出现**
- 1、2、3 报数
- "做了几次？"
- 任何需要按键才能继续的必经步骤

**状态矩阵**

| workout.status | coach.phase | 界面 |
|---|---|---|
| exercise_active | START_SET | 开场提示中，等待"开始"（也可自动） |
| exercise_active | REP_GUIDANCE | 主态：动作名 + 目标 + 在听 |
| exercise_active | — | 喊停追问（见 4.7） |
| paused | — | 暂停屏 |

### 4.6 组间休息 ★

- 倒计时（大数字，环）
- 下一组：动作 + 组次 + 目标
- 教练一句（≤30 字）
- 操作：**开始下一组**（语音）/ +15 秒 / 结束训练
- **退路卡**（仅在"吃力"后出现，见 4.8）

### 4.7 喊停追问 ★（组内子状态）

触发：用户说"累了 / 不行了 / 撑不住"

```
        ┌─────────────────────┐
        │   是累，还是哪儿不对劲？ │
        │     还剩 2 个。        │
        │                       │
        │  [ 就是累 ]  [ 不对劲 ] │
        └─────────────────────┘
```

- 一句话、无感叹号、**不劝说、不指责**
- 两个按钮只是兜底，语音答"累 / 疼"即可
- **累** → 教练推一把（"能顶就再顶一下"）→ 继续本组
- **不对劲 / 疼** → 立即进 4.9 安全态
- 同一组**只追问一次**；第二次说累 → 直接收工（进组间休息）
- 每一组重新计数

### 4.8 退路三选一 ★

出现时机：**吃力收工时**（不是每组都有）

两种作用域：

| 作用域 | 三个选项 | 副文案 |
|---|---|---|
| 本组还有 | 降一点 / 就这样 / 少做一组 | "下一组怎么走？" |
| 本动作已完 | 下一个轻一点 / 按原计划 / 少练一个 | "下一个动作怎么走？" |

- 卡片放在组间休息顶部，**不遮挡倒计时**
- 不选也有默认（按标准降档），**不催**
- 语音可直接说"听你的 / 我能行 / 少做几个"

### 4.9 疼痛安全态 ★

- 全屏、无红色恐吓、无医学判断
- 文案："先停下来，安全放下负重。"（+ 一句"今天可以到此为止"）
- 出口：结束训练 / 换个不疼的动作（**不允许**继续同一个动作）
- 之后的面板不再提供"开始下一组"

### 4.10 结算 ★

- 三个数字：时长 / 完成动作 / 完成组数
- 一句复盘（≤30 字，可带真实进步："这周比上周多 4 组"）
- 主按钮：记录详情；次：回首页
- **不要**：失败感、未完成惩罚、催打卡

### 4.11 训练后问卷 ★（唯一允许提问的地方）

三步、每步一句、可跳过：

1. 今天整体强度？（1–5，脸/圆点）
2. 目标肌群有感觉吗？（没感觉/有/很强）
3. 有没有不适？（没有/轻微/明显）

> 整场**只问这一次**。

### 4.12 进步（规律性）★

- 主卡：**"本周 3 次 / 18 组，比上周多 4 组"**（真实数字）
- 次卡：动作级对比（**仅当有真实次数时**出现；否则不显示，不要编）
- 章节点：当前章节进度
- 周柱状图：分钟/组数二选一，不要两个都放

### 4.13 记录列表 / 详情

- 列表一行一场：日期 · 目标 · 时长 · 完成度 · （提前结束标记）
- 详情：每动作每组（次数/重量/反馈），以及"这组的反馈被采纳了吗"

### 4.14 权限与错误态

| 场景 | 必须给什么 |
|---|---|
| 麦克风被拒 | 一句解释 + "如何开启"（分浏览器/系统）+ **可继续用按钮** |
| 语音不可用（如 Firefox 无 TTS） | 说明 + 降级方案（文字/按钮） |
| 网络中断 | "先按计划继续，稍后补记"（不丢训练） |
| 会话过期 | 一句人话 + 回到首页（不要白屏） |

## 6. 数据契约（每屏读什么）

| 屏幕 | 接口 | 关键字段 |
|---|---|---|
| 首页 | `GET /api/progress` | `relationship.text`、`nudge.text`、`program.status.text` |
| 课程地图 | `GET /api/programs/active` | `program.weeks[]`、`status.{weekNumber,chapter,completedSessions,totalSessions,nextSession}` |
| 计划生成 | `POST /api/workouts/preview` | 入参 `input` 或结构化字段（含 `equipment[]`） |
| 组内/组间 | `GET /api/workouts/active`、`POST /api/workouts/:id/actions` | `status`、`runtime.coach.phase`、`exercises[]` |
| 退路 | `actions` `coach_event{agency_choice}` | `accept_cut/hold_on/bargain/next_down/stay/skip_next` |
| 喊停 | `actions` `coach_message` | 服务端返回 `directive.text`（追问或收工） |
| 进步 | `GET /api/progress` | `volume.text`、`weekly[]`、`exercises[]` |
| 记录 | `GET /api/history` | `sessions[].record / sets[]` |

> 设计不需要改接口；缺字段先提，不要在前端编数据。

## 7. 动效与视觉

- 动效只用于**状态变化**，不用于"吸引注意力"
- 呼吸动效 ≤2 处/屏（当前听 + 当前组）
- 禁止：弹跳、闪烁、红点、音效轰炸
- 深色"夜场"方向继续用；对比度 ≥4.5:1

## 8. 验收清单（设计稿逐条打勾）

**硬约束**
- [ ] 组内每个操作都有语音等价，且"在听"可见
- [ ] 全流程只在两处提问：整场结束、喊停追问
- [ ] 没有任何惩罚性元素（无 hearts/断签/排行）
- [ ] 进度数字全部来自真实完成数据
- [ ] 剂量变化都有 ≤30 字的理由

**流程完整性**
- [ ] 20 屏齐全，且每屏有空态 / 加载 / 错误态
- [ ] 计划生成包含**器械多选**
- [ ] 章节地图含：章主题、节点三态、章末关卡、不设失败
- [ ] 休息页含退路三选一（两种作用域）
- [ ] 疼痛安全态独立，且之后不能继续同动作
- [ ] 恢复未完成训练的入口

**智能体验（十个瞬间）**
- [ ] 记得上次偏难 / 替你数 / 喊停追问 / 说太重就降 / 知道连续三周 / 说清为什么
- [ ] 感知两条（"喘起来说顶住"、"停 8 秒说喘匀"）**先预留位置，不实现**（当前静默观测）

## 9. 明确不做

1. 排行榜、hearts、断签惩罚、付费复活
2. 组内报数（1,2,3）
3. 每组问感受
4. 用推断值冒充完成度
5. 多步表单式计划生成（一次拿全）
6. 任何"必须点一下才能继续"的必经步骤
