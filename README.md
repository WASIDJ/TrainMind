# TrainMind

**说清你的目标、手边有什么器材、以前练过什么 —— AI 排出训练计划，并在你练的过程中不断改它。**

计划不是一张印好的表。你昨天那组做轻松了、今天肩膀有点酸、这周只练了两次，下一场的内容和剂量都会跟着变。

TrainMind 的目标是**一站式运动平台**，不是又一个健身 App。力量和活动度是第一个跑通的品类；篮球、足球、跑步这些项目的训练计划本质上是同一件事的复杂版本（多了周期、位置、技术动作和对抗强度），要走的是同一套「目标 + 器材 + 历史 → 生成 → 动态调整」的骨架。

---

## 一、核心闭环：三个输入，一次生成，持续调整

### 1. 三个输入

| 输入 | 用户怎么给 | 系统拿到什么 |
|---|---|---|
| **目标** | 一句话（"想练背""想减脂""想练全身"）或直接选 | 目标类型、优先级、想要的时长 |
| **可用器材** | 选徒手 / 哑铃 / 弹力带，以及在家 / 办公室 / 健身房 | 动作候选池的硬边界（没有的器械绝不出现在计划里） |
| **历史训练记录** | 自动读，不需要用户填 | 每个动作上次的重量/次数/难度反馈、各肌群近 7 天刺激量、上次训练距今多久 |

还有一层隐含输入是**当下的身体状态**：自报酸痛部位、疼痛信号、恢复状态。这些不是靠猜，是按规则直接改变候选动作集合。

### 2. 生成：多周课程

`Program → Week → Session` 三级结构。一次生成 4–24 周、每周 1–7 场，每场有明确的周次、章节（起步 / 建立 / 加深 / 巩固）和训练焦点。

**课程只决定"节奏和章节"，不决定剂量。** 每场模板里只存一句需求描述，真正的动作选择、组数、次数、重量，在每次开练时由规则引擎按当时的历史现算。所以第 3 周第 2 场不是一个固定快照，而是"这一场应该练什么"的实时答案。

### 3. 动态调整：三个时间尺度

| 尺度 | 触发 | 发生什么 |
|---|---|---|
| **组内**（秒级） | 你报"有点轻松 / 正好 / 有点吃力 / 做不完 / 疼" | 下一组的次数或重量立刻变（轻松 → 次数 +1；吃力 → 降一档；疼 → 锁死动作并跳过） |
| **跨场**（天级） | 上一次同类动作的实际表现 | 七种调整之一：`calibrate`（生疏了先校准）/ `maintain`（保持）/ `progress`（加次数或加重量）/ `regress`（回退）/ `reduce_volume`（减组数）/ `substitute`（换同目标动作）/ `avoid`（有疼痛史直接不排） |
| **周级**（跨肌群） | 各肌群近 7 天刺激量与恢复窗口 | 同一肌群每周超过 2–3 次不再加容量；24 小时内刚练过的部位不再排力量动作；酸痛部位优先排除 |

### 4. 留痕

每场训练留下可回放的事实记录：哪个动作、第几组、目标多少、实际多少、来源是什么。

次数分三态：**counted**（系统数的）/ **reported**（用户报的）/ **assumed**（按目标推定的）。**推定值永不参与"你进步了"的宣称**——所以界面上那句"从 8 次做到 12 次"是真账。

## 二、运动圈

围绕"练"的社区。它不是论坛，是让相近的人互相看见、一起把事做下去的地方。

**已经能用：**

- 账号（独立注册登录，scrypt 加盐，会话凭据只存哈希）
- 图文发布 + 照片（浏览器端压缩、每张 ≤600KB），四个话题：生活照片 / 训练经历 / 恢复日记 / 找同路人
- 关注与关注流（单向，第一天就开放，不等于获得私信权限）
- 点赞、评论、个人主页（昵称、方向、等级、粉丝关注数）
- **同路人匹配**：主动选择方向 / 阶段 / 环境 / 频率 / 时长，可主动分享当前计划的动作结构摘要；双方都启用匹配才互相推荐，输出可解释的共同点，不展示精确相似度，也不推断"身体相同"
- 恢复日打卡与等级（累计 0 / 3 / 7 / 14 / 30 / 90 / 180 / 365 日）
- 屏蔽、举报、内容隐藏、账号暂停等治理工具
- 数据导出与账号删除

**还没做**（`docs/COMMUNITY-IMPLEMENTATION.md` 有完整清单）：固定小圈、双向练友与私信、火花、共同周计划、附近约练与位置匹配、商品/优惠券核销、创作者认证。也没有部署到公网。

设计原则写在 `docs/COMMUNITY-PRD.md`：**不自动造用户、不造假计数、不为没有的能力放假按钮**。社区现在是真实但冷清的，界面如实说明。

> 命名：代码与界面里这个模块目前叫「社区」（`/community`、`src/community.ts`），产品口径上的「运动圈」是同一个东西。

## 三、现在到哪一步了

| 能力 | 状态 |
|---|---|
| 一句话生成单场训练 | 可用，真机验证 |
| 多周课程（4–24 周） | 可用，计划/执行显式分离 |
| 组内按反馈调剂量 | 可用 |
| 跨场按历史调剂量 | 可用（七种调整动作） |
| 肌群频次与恢复约束 | 可用 |
| 疼痛 / 酸痛 / 禁忌过滤 | 可用，且过滤没生效时会如实说明 |
| 全语音陪练（开始/暂停/下一组/报数/换动作） | 可用 |
| 教练叙事（LLM 只改说法，不碰数字） | 可用，失败回退模板 |
| 组内听觉感知 | 静默观测中，只记数据不打扰 |
| 运动圈（关注 / 同路人 / 发现） | 本地试用版可用 |
| **球类等其他运动项目** | **未支持**。当前动作库与目标类型只有力量与活动度；球类需要技术动作库、周期模型和对抗负荷，是独立的一块工作 |
| 后台推送（它主动来找你） | 未做，目前是应用内提示 |
| 公网部署与多设备账号 | 未做 |

一条硬边界：**剂量与安全只来自规则层**。LLM 和语音感知只决定"说什么、什么时候说"，永远不碰重量、次数、组数。组内话术 ≤30 字且不许反问，提问只发生在"整场结束"和"确实卡住"两个时机。

## 四、跑起来

需要 **Node ≥ 24**（用内置 `node:sqlite`）。无第三方依赖，不用 `npm install`。

```bash
./start-7b3.sh        # 推荐：带上 TTS / LLM / 叙事配置
# 或
npm start             # 裸启动，缺密钥时静默退化成模板话术
```

打开 http://localhost:3000/

- `/phone-preview.html` —— 手机壳演示版（可切账号、重载）
- `/?user=demo-investor` —— 直接进演示账号

**别直接 `node src/server.ts`**：会静默退化成"哑教练 + 模板话术"。密钥放 `~/.trainmind.env`（`chmod 600`），不进仓库：

```bash
TRAINMIND_CHAT_API_KEY=...   # LLM 叙事（缺失则回退模板）
TRAINMIND_TTS_KEY=...        # 语音播报（缺失则只显示文字）
```

### 演示数据

```bash
curl -s -X DELETE "http://127.0.0.1:3000/api/export?userId=demo-investor"
TRAINMIND_DEMO_USER=demo-investor TRAINMIND_DEMO_AS_HUMAN=1 TRAINMIND_APPLY=1 node tools/demo-seed.ts
```

重建后课程进度是 6/12 场。截图或演示前先重建，否则会落在"已有未结束会话"上。

## 六、代码结构

```
src/server.ts         HTTP 路由与静态资源（无框架）
src/core.ts           剂量 / 安全闸 / 训练状态机 —— 唯一能改数字的地方
src/muscles.ts        肌群账本：近 7 天刺激、恢复窗口、每周频次
src/program.ts        多周课程：Program → Week → Session
src/progress.ts       进步判定、关系进度、周对周
src/narration.ts      LLM 叙事层：包装指令、30 字上限、失效回退模板
src/perception.js     组内听觉感知（静默观测）
src/community.ts      运动圈：账号、发布、关注、同路人、治理
src/daily-report.ts   日报
src/telemetry/        冻结的 SetRecord v2 事件链（可回放）
public/               单页应用：index.html + visual-design.{js,css} + 各模块
knowledge/            动作库（含禁忌标签）、处方证据、替代动作
tools/                演示数据、素材拉取、数据修复
docs/                 PROGRESS.md（当前状态）、journal/（按日取舍）、各模块 PRD
```

数据存本地 SQLite（`trainmind.db`，**永不入库**——里面是真实训练与语音转写）。

只有**形态确实一致**的动作才配图；找到相似但不同的动作时宁可没图。重新拉取：`node tools/fetch-freedb-media.ts`。

## 八、协作约定

动手前先读 [AGENTS.md](AGENTS.md) 和 [docs/PROGRESS.md](docs/PROGRESS.md)。

每次实质改动：跑通测试 → 更新 `docs/PROGRESS.md` 与 `docs/journal/<日期>.md` → `git commit`，消息写清"改了什么、为什么"。

判断标准：**一个没参与当天对话的人，只看仓库能不能复原"为什么这么做"**。
